# 方案 C Playbook v1

本表定义可复用的问题形态，不储存具体问句或自动选择业务答案。脚本全量检查五个候选并保存每个候选的 `matched_features/blocking/status`；词法分数只用于检索排序。`decide` 输入为 `{question,pattern,source_ids,...}`，其中 pattern 必须来自本表，来源、指标和字段必须来自当前目录。CLI 将 `echo/transport_request_id/client_trace_id` 作为 input-only 字段剥离并记录，其他未知字段拒绝。

裁决后必须收敛：`clarify` 只在存在用户可回答且会改变结果的业务选择时发起原生 HIL；`reject` 直接解释阻断。正式查询精确限定后为空，报告该范围无记录；目标日期晚于来源最大日期时，可先用受限 `probe` 证明缺期。目录没有要求的指标时核对同名报表项目，仍无定义就说明缺项。计划或 SQL 被拒绝时先判断计划本身是否错误：新证据否定源、指标、期间或比例语义时重新取当前上下文、重新裁决并重建计划；仅 SQL 偏离正确合同时才修 SQL。enforce 同一 Run 的同类诊断三次无新证据后停止，连续六次不同诊断也停止。工具/模型故障不等于无数据，也不构成业务 HIL。

用户已明确日期、日度粒度、编码或合同类别时，先核对本源实际字段和项目值；摘要或期间定义与真实字段冲突是元数据修复问题，不要求用户改问月度。两个月不连续的比较可用覆盖中间月份的连续 typed 区间取数、只报告目标月份；业务期间、计划绑定和 SQL 范围必须相同。同编码时序值与指标信息名称、单位可分别附来源，不因缺统一快照水位就询问用户是否允许列示。

HIL 候选只列出已有证据支持且执行后有业务意义的选择：不提供未经证明的组织相加、层级包含关系、跨日期混合均价或“官方”名义；指标、比较基期和主体范围都影响答案时，一次问清必要槽位。若当前来源只提供样本价格，先说明不能称为全国官方均价，再询问用户是否改问一个指定日期、规格、价格类型的样本统计。

`proceed` 后把同一 typed 输入放入执行 `query_plan.business_intent`；执行入口按当前目录重裁决，核对源签名、正式指标、typed 期间、ratio 与 scope 字段。Ratio 输入需列明分子/分母项目、度量、粒度、零分母策略和 `definition_evidence`；双 scope 输入需分别列明源、实体编码、字段、ISO 时间区间与输出，并在计划中保留各自 `scope_id` 的实体 lookup。`comparison.mode=separate_listing` 时，每次正式 SQL 只选一个 scope、其实体 lookup 与物理源，分别返回并列示。证据文本和模型回显无法替代原生 HIL 事件鉴别，最终业务含义仍由当前模型和用户核对。

| ID / 版本 | 必要槽位与适用 | 阻断、反例与核对 |
| --- | --- | --- |
| `single_metric` / 1 | 来源、正式指标引用；单一口径取数 | 近似指标、实体或期间未确认则澄清；核对项目、实体、期间、单位和快照型指标的跨期可加性。 |
| `period_comparison` / 1 | 来源、指标、typed 自然区间 | 不把已生成 SQL 条件再解析为自然时间；期间不齐、累计与月发生混比时阻断；核对 ISO `[start,end)` 到存储编码。 |
| `ratio` / 1 | 来源、指标及有来源的分子、分母、粒度、零分母语义 | 比率不是两个项目值随意相除。仅准入同源项目全集物理过滤、两支条件聚合、精确分组及 `NULLIF(denominator,0)`；其余表达式拒绝或人工核查。 |
| `scope_comparison` / 1 | 两个独立 scope、源、主体与输出映射 | company/headquarters 可重叠；缺编码、快照水位或组织口径可比性时澄清。两支 CTE 各自物理筛选并映射输出。 |
| `category_distribution` / 1 | 来源和当前分类维度字段 | 职称等分类不是组织 Entity Role。字段无定义或把分类当主体编码时阻断；核对 GROUP BY 和项目条件。 |

`latest_period_snapshot` 是时间策略，不单独建 Playbook。候选同时合法且改变结果时返回 `playbook_conflict`，走原生 HIL；HIL 恢复后重新读取目录和裁决。无效源、未定义实体角色或非法 scope 直接拒绝。物理事实可用 `probe` 进行一次有目的的只读探查，然后重新裁决；前 50 个值不能宣称完整值域。

用户要求“含/包括/合并/加上总部、公司或子公司”时，即使用 `single_metric` 标签也要先核对目录是否定义这些组织的包含关系。当前目录只提供统计组织编码，不提供可证明的层级加总关系；`decide` 会给出 `scope_business_unconfirmed`。向用户用原生 HIL 确认是取公司编码单项、列示公司与总部两个值，还是明确可加总的其他口径。编码前缀、名称与数值不能证明 BGTA 已包含 BGTA00，也不能证明两者可相加；HIL 选项也不得暗示“公司口径通常已含总部”。未确认前不能给一个确定“含总部总数”。

HIL 选项不能把“用户提供若干编码”直接写成“按这些编码求和”，也不能把“月报中全部组织”写成可加总的集团人数；编码清单只解决成员范围，不证明组织人数互斥。用户只指定唯一可解析的主体且没有要求合并其他组织时，不要发起范围 HIL。

part_to_whole 比例要求分子项目集合包含于分母项目全集；a_over_b 允许不同项目集合，但仍须同源、同度量字段、同粒度。若分子与分母是两个不同项目（如“35 岁以下职工人数”÷“在岗员工人数”），`decide` 返回 `ratio_physical_shape_unsupported` 并在 SQL 前拒绝把它伪装成已验证的单扫描 ratio。可以说明本期自动验证不覆盖该形态；若需给数，必须分别以完整计划查询两项并由当前 Agent 人工核对相同组织、期间、单位后计算，不能删 ratio 绑定来让原 SQL 通过。

固定正反 fixture 及执行入口/探查回归由本地测试保留；它们证明已列形态的行为，未证明任意自然语言意图或最终答案的业务准确率。
