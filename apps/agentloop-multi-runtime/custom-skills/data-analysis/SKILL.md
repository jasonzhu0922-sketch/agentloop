# 数据查询与分析

完整问数链路属于本 Skill，由当前 Agent 使用当前会话模型完成业务判断。包内包含目录读取、SQL 校验、场景隔离、只读执行、审计、结果保存和可选 HTTP 接口的全部实现；不依赖另一个项目的代码或服务，不启动另一套模型流程。不调用自然语言整链路 `/api/runs`、`/api/runs/stream` 或 MCP `query`。规划、SQL、修正、工具结果和结论保留在当前 Runtime Run 中。

数据源定义与凭据由宿主在 Skill 根目录 `connections.json` 配置。使用 Runtime 提供的 `python3` 直接执行本包 `scripts/data_client.py`；脚本沿用启动它的解释器，依赖见 `requirements.txt`。无需用户提供项目路径或设置 `NL2SQL_PROJECT_ROOT`。配置仅由脚本读取，不回显凭据，不要求用户粘贴连接密码。通常无需启动 HTTP 服务。

## 工作流

1. **先取得用户明确的场景选择。** 用户必须以场景 id、场景名称或本任务的结构化 HIL 选择明确指定场景。用户未指定时，首先执行 `scripts/data_client.py select-scenario --output <workspace-file>`；该动作读取真实场景目录，输出标准 HIL 单选控制结构，由 Runtime 持久化并暂停当前 Run。等待用户选择后才能读取任何场景元数据、规划或执行 SQL；即使只有一个场景也必须确认。不得根据问题内容、数据相关性、默认配置或模型判断自动选择，不得以普通文字询问或展示 JSON 代替实际 HIL。用户已在本任务明确指定或通过 HIL 选择的场景有效，无需重复询问；先用目录校验其身份，精确绑定选择的 id，其他任务或其他 Run 中的选择不能自行沿用。元数据与查询始终显式传 `scenario_id`；用户改变选择时立即按新选择执行，不混用旧场景证据。HIL 结构及恢复规则见 [数据访问契约](references/input-contract.md)。
2. **理解问题并查目录。** 明确对象、指标含义、时间、输出粒度及比较范围。先读数据源索引，再获取相关表详情。使用真实物理字段、指标、术语、字段值域、关系和时间规则，不把示例或简称当成真实字段值。命令见 [数据访问契约](references/input-contract.md)。
3. **制定领域计划。** 依据 [规划与口径](references/planning.md) 将问题绑定到表、字段、时间编码、指标公式、组织层级和输出粒度。简单问数不增加机械轮数。只按已确认的关系与粒度 JOIN；独立来源分别查询。缺失业务定义才澄清，目录或小范围探查能确定的事实由你查证。
4. **生成并执行 SQL。** 由你生成 PostgreSQL SQL，通过 `scripts/data_client.py execute --request-json` 在同一次工具调用中传入 SQL 和独立参数数组，无需中间请求文件。执行前确认筛选值和聚合含义，使用目录中的 `schema.table`。包内执行器强制执行 SQL 策略、场景授权、只读角色、输出字段限制、超时、结果大小限制与审计。不自行写另一套数据库连接或读取连接密码来绕过执行器。
5. **核对与修正。** 检查状态、实际 SQL、`dataset.columns`、`rows` 和 `row_count`。空集合、NULL、策略拒绝和执行失败是不同结果。意外空值时核对对象、值域、期间与项目，必要时进行最小只读探查，依据证据修正 SQL。不要重复查询来恢复预览省略的数据，不把故障改写为无数据。
6. **分析并交付。** 单值问数只交付请求的数值、期间、实体、指标口径和必要来源，不扩写整份报表或组织结构。趋势、比较等任务再按需使用目录中的方法与 [分析方法](references/analysis-methodology.md)，通过可复核的代码或 SQL 计算。每个数值和实体描述对应具体结果行或计算输出，无法定位的内容不作为事实交付。完整数据保存在结果文件中，以场景、`query_id`、目录版本、SQL 和文件引用建立证据链。

## 证据与执行边界

- 用户问题决定目标，元数据和查询结果约束事实。目录中的方法建议不能自行增加用户未要求的业务条件。
- 字段值域与本次 DISTINCT 观测范围不同；组织别名、层级与合并口径需要证据，不猜等价、不混加报表项目或层级。
- `content_complete=true` 的回执包含完整原始响应，直接使用事实；大结果读取回执指向的完整文件或确定性计算。只看部分排序记录不能证明对象不存在。
- `dataset.row_count` 必须与完整 `rows` 一致；超过结果上限时明确失败，不交付未声明的部分成功。查询回执只证明执行事实，不能证明业务回答正确。
- `connections.json` 只作为脚本配置输入，不加入报告、工具参数或日志。连接或依赖不可用时指出具体阻塞，不询问无关项目路径、不改宿主授权、不启动替代服务、不降级直连。
- 本包按场景隔离，不提供用户级认证。HTTP 接口仅监听本机；只有用户明确要求 HTTP 形式时才启动包内服务。数据源业务数据只读，唯一数据库写入是配置目录数据库的查询审计表，不写业务表、不修改配置、不初始化数据库。
