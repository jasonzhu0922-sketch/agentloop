## 七、建模结论

### 查询事实

1. **表结构**：46列，其中22列为核心业务字段，4列为审计字段，4列已命名扩展字段（申请时间/理由/驳回理由/准入得分），3列有业务含义扩展（英文字母大写/chips号/cips号），13列为未使用预留字段。
2. **记录数**：精确4,114条。
3. **索引**：无显式索引和唯一约束。
4. **状态分布**：全部记录ACCT_STATUS="20"（已生效），无其他状态值。
5. **境内外分布**：境内3,973家（96.6%），境外9家（0.2%），其他132家（3.2%）。
6. **银行类型分布**：高度集中在类型9（1,642家）和类型5（1,611家），合计占比79.1%。
7. **关联字段**：TCBYH02通过TEMP6(银行代码)和APPLY_NO关联，TCBYH03/04通过ACCESS_ACCT_TYPE关联，TCBYH07通过BLACK_ACCT_TYPE关联。
8. **ACCT_APPROVAL_NO字段**：查询结果显示全部为空格（注册申请记录号未使用）。

### 建模推断

| 推断项 | 结论 | 依据 |
|:---|:---|:---|
| **表类型** | **主数据表（维度表/Slowly Changing Dimension）** | 存储银行静态属性信息，被多张下游事务/流程表引用 |
| **业务对象** | **银行（Bank）** | 每行代表一家银行的完整信息 |
| **逻辑主键** | **ACCT_TYPE_CODE（银行代码）** | (1) 字段语义为银行唯一编码；(2) 被TCBYH02/03/04/07等表作为外键引用；(3) TAX_NO有值为辅助唯一标识 |
| **数据粒度** | 一行一家银行 | 银行代码不重复，每行对应一家银行实体 |
| **SCD策略建议** | **SCD Type 2（带生效时间）** | 银行属性（评级、战略合作等）会随时间变化，需保留历史版本；当前ODS层仅保留最新状态 |

### 风险与缺口

1. **无唯一索引**：表无显式主键和唯一索引，存在重复银行代码的数据质量风险。建议验证 ACCT_TYPE_CODE 的实际唯一性。
2. **全部状态为"20"**：当前仅保留已生效记录，草稿和驳回记录可能被物理删除或不在本ODS表中，需确认是否影响数据完整性。
3. **TEMP字段混用业务数据**：TEMP1(申请时间)、TEMP2(申请理由)、TEMP3(驳回理由)、TEMP4(准入得分) 实际承载业务数据，但以TEMP命名，不利于理解和维护。
4. **股东背景大量为空**：ACCT_SHAREHOLDER_BACKGROUND有3,942条为空（95.8%），该字段数据质量较低。
5. **关联方式不统一**：TCBYH02通过TEMP6(银行代码)关联（非标准外键命名），TCBYH03/04通过ACCESS_ACCT_TYPE关联，TCBYH07通过BLACK_ACCT_TYPE关联，关联字段命名风格不一致。
6. **ACCT_APPROVAL_NO全空**：注册申请记录号字段全部为空格，可能为预留未使用或数据未同步。

### 建模建议

| 建议 | **建议进入候选模型** |

**理由**：
- 该表是银行主数据的核心维表，在同系列13张表中处于中心地位，被4张以上下游表引用
- 数据量适中（4,114条），字段业务含义清晰
- 逻辑主键明确（ACCT_TYPE_CODE），具备建模基础
- 建议DDM层将TEMP字段重命名为语义化字段名，并建立银行维度表，统一为下游提供银行基础属性
