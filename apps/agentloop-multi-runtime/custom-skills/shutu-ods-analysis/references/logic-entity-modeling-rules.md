# 逻辑实体建模判定规则

本参考文件用于补充 ODS 单表分析中的逻辑实体命名、字段类型识别、关系验证和输出口径。只有在字段命名、字段分类、主键/外部引用、关联关系判断不确定时才需要读取。

## 逻辑实体命名

- 逻辑实体名应表达当前表承载的业务对象和数据粒度，不直接照搬物理表名。
- 去除明显物理痕迹：`ODS`、系统前缀、技术后缀、环境/部署标记、`表` 字。
- 表中文名为 `XX信息主表` 时，通常识别为 `XX主信息`，而不是泛化成更大的业务对象。
- 表表示对象侧面时，采用 `对象 + 侧面/范围`，例如 `账户扩展配置`、`合同明细`、`组织层级关系`。
- 如果样例数据和稳定关联关系显示表名/字段名误导了对象语义，应以真实数据关系修正逻辑实体命名。

## 属性命名

- 属性名应完整表达“谁的什么特征/状态/时间/标识/数量”，避免只有 `状态`、`编码`、`时间` 这类孤立特性词。
- 字段中文名过短时，从逻辑实体名中提取对象词补全，例如 `状态` -> `账户状态`，`创建时间` -> `记录创建时间`。
- 字段中文名明显错误、重复或过泛时，结合字段英文名、字段注释、相邻字段和样例值重新命名。
- 人员展示字段如果样例值是 `登录名 | 姓名`、`姓名（工号）`、备注文本等，不要命名为 `XX标识`，优先命名为 `XX负责人描述`、`XX审批人说明` 等描述性属性。
- 布尔/开关字段按实际取值命名为 `XX开关`、`XX标记`、`是否XX`。

## 字段类型

字段至少分为以下类型，并在报告中显式说明判定依据：

| 字段类型 | 含义 | 常见信号 |
|:---|:---|:---|
| 数据类型字段 | 描述当前实体自身特征、状态、时间、金额、文本、枚举等 | 名称、状态、日期、金额、描述、备注、类型码 |
| 主标识字段 | 唯一或近唯一识别当前实体实例 | 主键、唯一索引、业务单号、UUID、稳定编码 |
| 外部引用字段 | 引用其他实体实例，用于形成表间关系 | 目标对象 ID/UUID/CODE/NO、父级标识、来源/目标对象标识 |
| 准标识字段 | 字段类型可归为数据类型，但实际值稳定承担标识或关联作用 | ENAME、CODE、NAME、路径、业务编码等 |

判断要求：

- 不能仅凭字段名包含 `ID`、`UUID`、`CODE`、`NO`、`NAME` 就判定为对象关联字段。
- `UUID/GUID` 更倾向于主标识或外部引用，但仍要结合样例值体系确认。
- `ID` 可能是业务可读标识，也可能是 UUID；必须抽样查看真实值。
- `CODE/NO/NAME/ENAME` 如果只是状态码、类型码、分类码，应作为数据类型字段，并补充枚举含义；如果稳定唯一标识对象，可作为准标识字段参与关系判断。
- 审计字段通常先作为数据类型字段处理，即使值看起来像用户标识，也不要先入为主判成外部引用。

## 共性字段规范化

大量 ODS 表中重复出现的生命周期、审计、归档字段应采用统一命名：

| 常见字段语义 | 推荐属性名 | 字段类型 |
|:---|:---|:---|
| created_by、creator、create_user | 记录创建者 | 数据类型字段 |
| created_time、create_time、gmt_create | 记录创建时间 | 数据类型字段 |
| updated_by、modifier、last_modified_by | 记录修订者 | 数据类型字段 |
| updated_time、modify_time、last_modified_time | 记录修订时间 | 数据类型字段 |
| archive_flag、is_archived | 记录归档标记 | 数据类型字段 |
| archive_date、archived_at | 记录归档日期 | 数据类型字段 |

## 关联关系识别

- 同前缀表只是候选，不等于直接关联表；最终必须结合字段语义、样例值和 SQL 命中结果。
- 优先识别 `外部引用字段 -> 主标识字段`。
- 其次识别 `主标识字段/准标识字段 -> 主标识字段/准标识字段`，适用于同一对象的主表、扩展表、发布表、映射表。
- 不要把 `外部引用字段 -> 外部引用字段` 默认识别为正式关系，除非语义明确且样例验证支持。
- 关系表通常包含多个外部引用字段，表示对象与对象之间的挂接、授权、映射、层级、标签、审批等关系；不要误识别为主信息表。
- 一般不建立自关联；只有层级语义明确时，才可保留 `父级标识 -> 当前标识` 自关联。
- 对来自同一系统不同部署实例或环境后缀的 ODS 表，优先尝试同后缀表之间的关联，再考虑无后缀主表。

## SQL 验证口径

候选关系必须尽量验证以下信息：

- 左侧关联字段非空数。
- 右侧目标字段非空数。
- 实际匹配数和样例匹配值。
- 是否存在空串、空白、默认值、占位符导致的伪匹配。

关系是否成立以“主交集稳定 + 语义合理”为核心，不要求所有记录 100% 命中。若匹配主要来自空值或默认值，应判定为无效关系。

## 样例值体系

对 `ID/UUID/GUID/CODE/NO/NAME/ENAME` 等标识类或准标识字段，应抽取 1-5 个非空样例，观察：

- 值长度和格式。
- 是否为随机 UUID、业务编码、单号、路径、名称或展示文本。
- 是否存在稳定前缀或编码模式。
- 是否与候选目标表的主标识值体系一致。

样例值体系优先级高于字段名表象。字段名相似但样例值体系不同，不应强行建立关系。

## 输出要求

- 报告中对关键字段写明字段类型、建模用途和判定依据。
- 业务编码字段要说明枚举或值域口径；不清楚时标注“待补业务口径”。
- 关联关系要写明字段级关联条件和 SQL 验证摘要。
- 当关系确认暴露出原逻辑实体名或属性名误导时，应在结论中同步说明命名修正依据。
