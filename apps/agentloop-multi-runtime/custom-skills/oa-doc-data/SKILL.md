# OA 文档数据

本 Skill 是 OA 公文、证照和文件的只读取数边界。它负责把用户明确提供的工号、时间范围、结构化条件和全文关键词映射为受控查询，返回接口针对该工号返回的原始记录、正文与附件内容、分页总量和预览链接；不负责摘要、内容问答、多文档比较或最终业务结论。

## 使用边界

需要摘要、内容问答、跨文件归纳、差异比较、时间线或主题分析时，先加载 `oa-doc-analysis`，由它确定证据需求并委派本 Skill。只有用户明确只要文件列表、原始内容、总数、查询条件、字段口径或预览链接时，才能直接交付本 Skill 的结果。

不要使用本 Skill 起草或改写公文、解释政策制度、查询工商股权、处理 HR 审批材料、执行督办催办，或发送邮件。

## 执行器

OA 搜索是普通 HTTP POST 接口，不依赖 Baowu Connector。调用本包执行器的 `search-documents` 动作；执行器从 `OA_DOC_ENV_FILE` 指向的部署私有配置读取接口地址、`appId` 和 `accCode`，模型从用户请求中提取工号并通过 `request-json.userId` 传入。

- 只调用执行清单中声明的 `search-documents`，不自行拼装带凭证的 HTTP 请求。
- `request-json` 必须包含 `userId`；它只能来自用户在当前请求或明确上下文中提供的工号。按字符串原样传递并保留前导零。
- 缺少工号时先请用户补充。不得使用 AgentLoop 登录 ID、邮箱、姓名推断、默认工号或模型猜测代替。
- `request-json` 不得包含 `appId` 或 `accCode`。这些凭证只由脚本从部署私有配置注入。
- 如果执行器未注册、配置不完整或服务不可用，停止并报告缺失能力。
- 相对日期使用运行上下文中的权威当前日期计算，并在回执中记录实际日期范围。

## 查询参数

以执行清单和脚本校验为准，将下列结构序列化为 `request-json`：

```json
{
  "userId": "001234",
  "timeRange": {
    "rangeType": "0",
    "startTime": "20250801",
    "endTime": "20250831"
  },
  "keyword": {
    "fromLocation": "集团办公室",
    "emergencyLevel": "加急"
  },
  "text": ["数字化转型"],
  "contentFlag": "1",
  "attachmentContentFlag": "1",
  "pageSize": 10,
  "pageNo": 0,
  "reason": "根据用户请求检索指定工号的 OA 文件"
}
```

字段规则：

- `userId` 是必填工号字符串，只能使用用户明确给出的值；不要转成数字、删除前导零或替换为 AgentLoop 登录 ID。
- `timeRange.rangeType` 的 `0` 表示来文日期，`1` 表示接收日期；日期使用 `yyyymmdd`。
- `keyword` 只放能明确映射的精确字段：`oaType`、`docType`、`documentNumber`、`fileNumber`、`emergencyLevel`、`fromLocation`、`drafterName`、`drafterCode`、`nodeName`、`ifHandled`。
- `text` 放标题、主题、事项和正文自由关键词。结构化条件与全文词可以同时使用。
- 摘要或问答取数默认请求正文和附件解析内容；只列目录时按最小数据原则关闭不需要的内容字段。
- `pageSize` 默认 10，最大 100；`pageNo` 默认 0。用户要求全部、总数或完整汇总时，根据响应的 `count`、`pageNo`、`pageSize` 拉取后续页。
- 用户只要求某一时间段的文件且没有其他条件时，只传时间范围，不虚构关键词。

## 受控流程

1. 从上层证据需求或用户请求提取明确工号、日期、精确条件、全文词和正文/附件读取需求。
2. 缺少工号时先请求用户补充；缺少时间范围且宿主没有业务默认策略时也请求澄清，不默认扫描全部历史数据。
3. 调用 `search-documents`，保留实际工号、查询参数、总数、分页信息和原始字段。
4. 按请求完成必要分页。不得把第一页条数当作总量，也不得把未取全结果声称为完整结果。
5. 返回结构化回执；不要基于正文做摘要、比较、推断或管理建议。

## 证据回执

回执至少保留：

- `request`：用户明确提供的工号、实际日期范围、精确条件、全文关键词、内容标志和分页策略。
- `accessScope`：结果仅代表部署凭证下接口针对指定工号返回的范围；Skill 不验证该工号与 AgentLoop 登录用户的归属关系。
- `count` 和 `returnedCount`：服务端总量与当前页取得数量；响应结构无法识别时明确标记未知。
- `upstreamResponse`：OA 服务返回的完整原始 JSON。
- `caveats`：空结果、响应结构未知、内容未解析、分页未取全、字段缺失、权限或服务限制。

把执行器返回的完整结构化结果或 `contentLocation.path` 交给 `oa-doc-analysis`。摘要、手工复制的片段或模型记忆不能代替原始回执。

## 安全与失败

- 不输出凭证、认证头、内部调试载荷或查询结果之外的无关个人信息。
- `forbidden` 或权限错误时停止，不改用其他工号、不重试绕过。
- 空结果必须回显实际查询条件，不用相近文件或模型知识补造结果。
- HTTP、超时或服务错误立即停止并报告安全错误，不在错误中回显凭证或原始响应体。
- 查询结果不替代正式公文原件、证照原件或审批文件。
