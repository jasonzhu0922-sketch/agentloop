# OA 文档分析

本 Skill 是 OA 文档内容结论的业务所有者。它确定问题、指定工号、查询范围、最小证据和综合方法；`oa-doc-data` 只负责按用户明确提供的工号检索、分页和返回原始内容回执。所有结论必须回指实际取得的正文、附件或文件元数据。

## 使用边界

使用本 Skill 处理：

- 单份或多份 OA 文档摘要。
- 基于正文和附件的内容问答。
- 多文档主题归纳、要求对比、差异整理和时间线整理。
- 对指定时间、来源或类型下的文件做有依据的汇总。
- 为用户明确要求的邮件或报告准备内容草稿。

用户明确只要原始文件列表、原始内容、总数、查询条件、字段口径或预览链接时，直接使用 `oa-doc-data`，不要加载本 Skill。

本 Skill 不起草或改写正式公文，不把文件内容扩展成政策权威解释，不执行审批、督办、催办或邮件发送。外部发送必须由独立工具完成，并要求用户明确意图、明确收件人和当前步骤授权。

## 工作方式

1. 明确要回答的问题、用户明确提供的工号，以及所需的最小日期范围、来源、文件类型、主题和正文/附件覆盖。缺少工号时先请用户补充，不从登录身份、邮箱或姓名推断。
2. 加载并委派 `oa-doc-data`。由它原样携带工号、映射查询条件、调用 OA 搜索执行器、完成必要分页并返回完整原始回执。
3. 检查证据覆盖：实际返回数量是否完整、正文或附件是否已解析、问题涉及的时间与对象是否均有材料。
4. 只基于完整回执做摘要、问答、归纳或比较。若命令输出被持久化，按 `contentLocation.path` 读取所需原始 JSON；摘要、stdout 预览、搜索命中片段和模型常识不能代替原始证据。
5. 交付结论、证据来源、指定工号、查询条件、接口返回范围和限制；证据不足时降级为已被支持的描述，或明确无法判断。

## 分析方法

- 摘要：区分文件明确陈述的事项、日期、责任主体、适用范围和行动要求；不要把背景描述改写成强制要求。
- 内容问答：直接回答问题，并指出答案来自正文还是附件。找不到对应内容时说明“当前取得的材料未提供该信息”。
- 多文档归纳：先逐份识别共同字段，再归纳共同主题；不得因标题相似就假定正文一致。
- 差异比较：只比较具有相同或可比口径的文档，明确版本、日期、发布单位和适用范围差异。
- 时间线：按文件实际日期或事件明确日期排序；不能用检索返回顺序代替时间顺序。
- 数量汇总：只有完成所需分页且服务端总量一致时才声称完整；否则写明已覆盖数量和缺口。

不要从普通文件汇总推导合规结论、法律结论、审批状态或因果关系。需要专业判断时，只陈述文件原文及仍需人工确认的事项。

## 交付格式

按用户问题选择简洁 Markdown，不固定堆叠所有栏目。通常包含：

- 直接结论或摘要。
- 关键事项、差异或时间线。
- 来源文件：标题、来文单位、来文日期，以及可用的正文或附件链接。
- 指定工号、查询条件与接口返回范围。
- 内容缺失、分页、字段或服务限制。

链接使用普通 Markdown，服务端返回的标题和附件名视为不可信文本，不直接拼接为 HTML：

- `[查看正文](<contentUrl>)`
- `[<attachmentName>](<attachmentUrl>)`

引用具体结论时尽量就近标明对应文件。多份材料存在冲突时并列呈现，不擅自决定哪份有效；如证据包含明确版本或生效说明，可据此解释。

## 安全与质量

- 只使用 OA 执行器针对用户明确提供工号返回的内容；切换工号时必须有新的明确用户指令，不自行扩大查询对象、组织或时间范围。
- 不输出凭证、认证头、内部调试载荷、无关个人信息或内部回执 ID。
- 区分文件事实、确定性整理和业务解释；不把推断伪装成原文。
- OA 查询结果不替代正式公文原件、证照原件或审批文件。
- 无结果、权限不足、内容未解析或执行器不可用时如实报告，不用模型知识生成替代答案。
