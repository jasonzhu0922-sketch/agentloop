# 钢材市场分析方法论

本参考由上层 `steel-market-analysis` 使用。它将业务问题转为最小可验证数据计划，再用 Python 计算并解释；不把行业常识、新闻或推断当作数据库事实。

## 一、先定义研究对象

“某钢种市场走势”不是一个天然唯一的序列。每次分析先固定或确认：

- **产品口径**：品种、牌号、规格、工艺与质量等级；例如“40Cr”与“42CrMo”不能因名称相近而视为同一钢种。
- **市场口径**：城市/区域、市场类型、钢厂或来源。只有研究对象明确为汇总指标时，才能把它称作区域市场价格。
- **指标口径**：市场价格、出厂价格、库存、产量、成交、原料、期货或其他；单位和频率是口径的一部分。
- **时间口径**：起止日期、日/周/月频率和比较基期。数据覆盖外的期间只能报告“库中无可用观测”，不能外推。
- **问题类型**：描述趋势、比较价差、解释供需、评估成本利润或观察期现关系。不同问题需要不同指标组。

若用户只说“分析 2025 年 11 月某钢种走势”，而候选同时包含多个规格、城市或钢厂，先列出少量候选及其单位/地区/品类，要求确认；不得暗自选取或混合。

## 二、研究问题与最小指标组

| 分析模式 | 最小原始数据 | Python 计算 | 可得结论 | 不可直接得出 |
| --- | --- | --- | --- | --- |
| 单一价格趋势 | 一个已确认 `INDEX_CODE` 的同频价格序列 | 先识别每日单值或多值形态；再计算单值变化或每日区间/分布变化、峰谷和覆盖 | 数据形态支持的价格水平、区间移动或阶段特征 | 供需或政策导致价格变化 |
| 区域/市场价差 | 同钢种、规格、单位、频率的两个或多个地点序列，且日期对齐 | 同日差值、价差区间、价差扩大/收敛 | 已确认口径间的价差变化 | 跨区域套利是否可行、物流成本原因 |
| 品种/规格价差 | 同区域、同市场、同单位、同频率的两个明确品种或规格 | 同日差值/比率、价差拐点 | 相对价格变化 | 产品替代或利润传导 |
| 供需验证 | 至少一个价格序列，加同口径库存、产量、成交/表观需求中的可用指标 | 同期方向、滞后关系描述、覆盖缺口 | 指标是否同向或背离 | 因果关系、完整供需平衡表 |
| 成本/利润观察 | 成品价格与同口径成本指标；利润还需明确成本公式和系数 | 价差、已声明公式下的估算利润 | 已声明假设下的价差/估算 | 钢厂真实利润或现金成本 |
| 期现/基差 | 同品种、质量、地点、交割规则与日期可对齐的现货和期货序列 | 同日基差、基差区间与变化 | 已定义口径下的基差走势 | 无风险套利机会或交割可行性 |

当前数据库是否存在某一类指标，必须通过 `preflight-catalog` 暴露的字段和值域以及 `discover-indicators` 的候选结果验证；`list-indicators` 只用于已知目录名称的兼容查找。缺少最小指标组时，降级为已有序列能够支持的描述性分析，并把欠缺指标列为下一步数据需求。降级不是停止分析：只要已有数据仍能回答问题的一部分，就交付该部分及其边界。

## 三、按可得数据确定最终方法

取数前的方法是研究假设，取数后的数据形态才决定能够交付多强的结论。对每个指标先归入以下形态，再选择分析路径：

| 实际数据形态 | 可采用的方法 | 必须避免 |
| --- | --- | --- |
| 无观测 | 只报告已验证的指标身份、查询范围和无观测事实 | 用常识补数或虚构走势 |
| 只有一个观测日期 | 报告该日观测集合、数值范围和口径 | 声称形成时间趋势 |
| 每日唯一值，日期覆盖足够 | 单值时间序列：路径、首末变化、阶段高低和必要的波动描述 | 把首末变化直接解释为原因或预测 |
| 同日多条但数值相同 | 当前返回字段下的数值水平一致；将附加观测次数作为数据质量信息 | 把次数当作价格权重、新增价格点或底表完全重复的证明 |
| 同日存在多个不同值，且没有区分字段 | 每日观测集合/区间：不同值个数、上下界、区间宽度和边界移动 | 任意选均值、中位数、最小值或最大值冒充唯一日价 |
| 多个指标满足可比性闸门 | 按共同日期做价差、比率或同向/背离分析 | 错位日期相减或混合不同单位/频率 |
| 理想指标组不完整 | 退到单序列或部分指标描述，并列出无法完成的验证 | 因无法归因就拒绝描述已有数据 |

“同日多条观测”只是行形态，不等同于“重复数据”。必须进一步区分：当前返回字段下同日同值的附加观测、同日多个不同值，以及有额外字段可解释的不同报价层级。只有原始数据提供稳定的层级、时点、版本或其他业务键时，才能拆成更细序列；否则保持观测集合，不自行归并，也不把未返回字段上的未知差异判成完全重复。

## 四、数据计划与取数节奏

每轮分析在调用下层前形成一个简短计划，至少说明：研究问题、每个指标在结论中的角色、筛选口径、日期范围、频率、可比性检查、理想分析方法及缺数时的降级方法。计划只包含完成本问题所需的最小指标组。

这个计划和随后的叙事由 LLM 完成，不由 Python 生成。Python 只接受已取得的原始行并计算数值事实；它不知道用户的决策问题，也不能决定某项变化是否构成市场趋势、指标背离、风险信号或需要补数的缺口。

1. **目录预检与定位**：先调用 `preflight-catalog`，用目录的真实字段样例理解用户描述；无论样例是否出现用户值，都必须将省份、城市、区县、大区、市场、来源、生产企业、品种、规格和指标口径拆为 `discover-indicators` 已映射的同名字段并调用该动作。先用稳定维度定位候选；如果某个目录列为空且完整 `INDEX_NAME` 含有对应的规格或牌号，则用一个明确名称片段收窄、以完整名称确认，不用整段带分隔符的自然语言规格去匹配空列。阅读候选的 `indicator_id`、名称、单位、频率、行政区划、生产企业、来源、市场和口径。不能把完整用户语句直接作为名称关键词；预检未映射的字段须作为数据映射缺口报告。
2. **确认**：候选不唯一时，请用户确认；候选唯一且名称已包含完整规格/市场口径时，记录该 `INDEX_CODE` 与选择理由。
3. **精确取数**：按已确认 `INDEX_CODE` 调用 `query-series-by-id`，每个指标和时间窗单独取得受限批次。只有探索性搜索才用关键词 `query-series`，并把多口径结果视为待确认。
4. **逐批保存**：将每个返回 JSON 保存至 Run 工作区，保留 `receiptId`、查询模式、日期范围和截断标记。遇到 200 行上限时缩窄时间窗或拆分相邻区间，不能静默丢弃早期数据。
5. **可比性闸门**：比较前逐项检查单位、频率、产品/规格、市场口径和日期交集；任一未通过，就只分别描述，不生成价差、比率、排名或聚合。

## 五、Python 计算纪律

- `analyze-series` 先生成不带业务结论的序列画像：观察数、唯一日期数、每日数值集合/区间、同日多值、当前返回字段下的同日同值附加观测、首末单值变化（仅在唯一时）、首末区间边界变化、极值和日期缺口。这些是后续方法选择的计算事实，不是固定报告模板。
- 单值序列可以计算首末绝对/相对变化；同日多值且缺少区分字段时，保留每天的不同值和区间，不能为了得到涨跌幅而选取代表值。此时可描述区间上下界如何移动，但必须明确它不是唯一日价的涨跌。
- 跨序列计算先以日期内连接建立共同样本，再计算价差、比率或方向关系；报告共同日期数及各自被排除的日期，不能以错位日期相减。
- 只有在频率一致且取到了对应可比基期时才计算环比/同比；不能把日度首末变化称为月环比或同比。
- 计算代码、输入文件路径、来源 `receiptId` 与输出必须留在 Run 工作区。Python 输出是派生证据，不替代下层的原始数据库回执。
- 遇到零除、无数值、同日多值、同日同值附加观测、日期缺口、截断或不同单位时，保留为显式 caveat，不用插值、补零、擅自聚合或隐式单位换算掩盖。

## 六、解释与写作框架

按“事实 → 解读 → 假设 → 缺口”输出：

1. **结论与方法**：用一两句说明最终采用的方法和已确认口径在指定区间的可观察变化；这是描述，不是预测。若从理想方法降级，紧接着说明原因。
2. **数据口径**：列出每个 `INDEX_CODE` 对应的名称、单位、地区/品类、频率、日期范围，以及会影响判断的记录形态和截断情况。
3. **关键数据变化**：LLM 选择与研究问题相关的 Python 具体计算值，并按指标角色组织为单值趋势、每日区间移动、价差、同向/背离或阶段特征；禁止把首末值当作所有方法的默认主线，也不要原样粘贴计算摘要。多序列时先说明共同样本和可比性。
4. **业务解读**：LLM 将价格、库存、产量、成交、成本或期现指标的同向/背离描述为观察，并说明该观察如何回答用户问题。只有具备额外可核验来源时，才将供需、政策、成本或宏观因素写成已验证解释；否则标注为待验证假设。
5. **限制与下一步**：明确数据缺口、口径不一致、样本不足或日期截断；只建议与当前决策有关的下一批指标。

不要将单城市、单钢厂或单规格报价泛化为全国市场；不要将相关性写成因果，更不要把数据库未覆盖的月份、品种或基本面用常识补齐。
