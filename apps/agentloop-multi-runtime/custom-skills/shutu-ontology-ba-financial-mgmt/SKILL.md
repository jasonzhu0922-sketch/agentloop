# 集团财务管理业务架构技能

本技能用于识别和管理集团财务管理的**业务规则**、业务流程、业务动作，并为业务动作设计对应的 MCP 工具。业务流程按「财务应用」归纳 18 个流程（源自《业财事项汇总表》236 项业财事项，代表性动作见正文、全量明细见 `docs/业财事项汇总表.md`）。

> **AgentLoop 接入边界**：本发布副本仅提供只读规则与口径解释，不授予付款、审批、记账、主数据变更或任何财务系统操作能力。规则结论须标明仍需财务领域专家确认。

> **业务规则来源**：以下业务规则须经财务领域专家审核确认。

## MCP 工具命名规范

- 以 MCP 服务实际注册的工具名称为准
- 工具名称、功能描述、输入参数、返回值应与 MCP 服务代码保持一致
- 同一业务动作在本技能中只保留一个对应工具名称

## 业务规则

### BR-01 会计核心概念：账面金额 ≠ 逐笔明细汇总

- **规则描述**："账面金额/科目余额" = **总账余额信息表**的期初余额/借方发生额/贷方发生额/期末余额，按科目代码+会计期查
- **错误做法**：用逐笔明细表 SUM 代替科目余额
- **正确查法**：`T_DWD_FACT_CWGL_GL_TOTAL_AMT_INFO`，WHERE `COMPANY_CODE` + `ACCT_TITLE_CODE` + `ACCT_PERIOD_NO`；注意 LAST_FLAG（Y=末级明细，空=汇总行），SUM 时需排除汇总行避免重复计数

### BR-02 会计口径：发生额查凭证不查余额

- **规则描述**："发生额" = **凭证明细表** `SUM(ACCT_AMT)`；余额表含汇总行/明细行重复计数，**不能查发生额**
- **正确查法**：`T_DWD_FACT_CWGL_VOUCHER_DETAIL_INFO`，WHERE `COMPANY_CODE` + `ACCT_TITLE_CODE` + `ACCT_PERIOD_NO` + `DEBIT_CREDIT`（1=借方，2=贷方）

### BR-03 税务口径：已认证通过按认证日期

- **规则描述**："已认证通过" = `AUTH_RESULT='00'`，且按 **AUTH_TIME（认证日期）** 筛选，不是开票日期或税款所属期
- **三个日期字段区别**：PAPER_DREW_DATE（开票日期，发票开具日）/ AUTH_TIME（认证日期，税务局认证日）/ SKSSQ（税款所属期，部分账套为空）

### BR-04 税务规则：简易计税需合并科目

- **规则描述**：差异分析时，简易计税 `2221026` 和一般计税销项税 `2221010020` **需合并查询**，单查一个科目差异无法解释

### BR-05 标财归属码体系：7 归属 vs 8 归属

- **规则描述**：7 归属（751管理费用/741销售费用/730主营成本等）：`ID_CODE` 直接存 8 位责任中心编码；**8 归属**（810生产成本/820制造费用等）：`ID_CODE` 全是"40"（汇总码），真正责任中心在 **`ADD_CODE_1`**（13 位=8 位责任中心+5 位成本科目），需 `SUBSTR(ADD_CODE_1,1,8)` 拆分
- **归属码末 3 位**：751=管理费用 / 741=销售费用 / 730=主营成本 / 753=科研费用 / 810=生产成本 / 820=制造费用

### BR-06 会计规则：内部往来科目余额查询

- **规则描述**：内部往来（科目 2351010）是**正常的往来科目**，月末有明确余额（且与对方公司方向对称——一借一贷）。"挂账"查询应查总账余额信息表（看余额）+ 凭证明细表（看发生额和摘要），不能只查应收账款表
- **数据表选择**：查内部往来余额用 `T_DWD_FACT_CWGL_GL_TOTAL_AMT_INFO`（全量总账余额信息表），**不能用** `T_ZZFX030`（"总账科目余额"表，只含应收应付往来科目段 1121/1122/1123/1221/2201/2202/2203/2211/2241，不含 23 开头科目）

### BR-07 资产管理规则：资产状态与总账口径对应

- **规则描述**：固定资产余额验证时，只有 `ASSET_STATUS=11`（已抛帐/在账）的资产计入总账余额；`50`（已报废）/`56`（处置转出）不计入。汇总时须按状态过滤
- **资产大类→科目映射**：0=使用权资产 / 1=房屋及构筑物 / 7=运输设备 → 对应总账科目 1601010~1601090

### BR-08 凭证编码规则：凭证号跨月不唯一

- **规则描述**：凭证号按**会计期循环编号**（如 EBZ1000010 每月重置），同一凭证号在不同月份代表不同凭证。跨月 JOIN 需加 `VOUCHER_DATE`（或 `ACCT_PERIOD_NO`）

### BR-09 会计口径：余额查总账余额表不查明细账龄表

- **规则描述**："余额"类查询应定位含"余额"字样的期末余额表（总账余额信息 `T_DWD_FACT_CWGL_GL_TOTAL_AMT_INFO`），非逐笔明细账龄表。余额表看期末存量，明细表看期间流量
- **正确查法**：`T_DWD_FACT_CWGL_GL_TOTAL_AMT_INFO`，WHERE `COMPANY_CODE` + `ACCT_TITLE_CODE` + `ACCT_PERIOD_NO`，取 `END_AMT`（期末余额）

### BR-10 会计规则：凭证借贷方金额不可相加

- **规则描述**：同一张凭证借贷方金额必然相等（借贷平衡），SUM 时须按 `DEBIT_CREDIT` 区分方向（`1`=借/`2`=贷），不可跨方向相加
- **正确查法**：`T_DWD_FACT_CWGL_VOUCHER_DETAIL_INFO`，WHERE + `DEBIT_CREDIT`（1=借方，2=贷方），取一方 `SUM(ACCT_AMT)`

### BR-11 会计规则：关账与会计期状态

- **规则描述**：关账的本质是将会计期状态从"已开账"(1)变为"未开账"(0)。查询关账操作须同时查"会计期"表（`BFMSXAAA.TAAAA01`）的 `ACCT_PERIOD_STATUS` 字段——这是关账最终状态落点，"关账控制"只记录执行过程。三层记录：月结族群 `CLOSE_TIME` → 关账控制 `ACCOUNT_END_TIME` → 会计期状态变更 `REC_REVISE_TIME`
- **正确查法**：`BFMSXAAA.TAAAA01`，WHERE `COMPANY_CODE` + `ACCT_PERIOD`，取 `ACCT_PERIOD_STATUS`（0=已关账，1=已开账）

### BR-12 票据规则：回款判断链路（签收→认领→抛账）

- **规则描述**：票据回款是**三步链路**：①签收——查电票签收表 `DRAW_PAPER_STATUS`（60=签收成功→进入下一步；11/21/61=驳回/拒绝→不会回款；10=接收→待签收；30=失败；31=撤销）；②认领——查原始票据档 `T_DWD_FACT_CWPJ_RAW_PAPER_INFO`（有记录=已认领并生成收条号，无记录=等认领）；③抛账——查同表 `RECEIPT_STATUS`（6=已抛账已下发；0=待处理等抛账）。DWD RAW_PAPER_INFO 是**准实时入口**，优于 TASSAA2 批量表（有写入延迟）
- **正确查法**：① `BFMSXAAN.TAFANBBN` WHERE `SETTLE_USER_NAME LIKE '%付款方%'`，取 `DRAW_PAPER_STATUS`；② `T_DWD_FACT_CWPJ_RAW_PAPER_INFO` WHERE `PAPER_NO`，取 `RECEIPT_STATUS`。⚠️ 注意 `RAW_PAPER_INFO.RECEIPT_STATUS` 与 `TASSAA2.RECEIPT_STATUS`（0=录入/3=接收/6=入账）、`TASSAA1.RECEIPT_STATUS`（0=待收款…）语义各不相同

### BR-14 收款规则：收条"未入账"判断（查 ODS 源表）

- **规则描述**："未入账收条"不是独立实体，是收款状态判断概念：`TASSAA2.RECEIPT_STATUS='0'`（录入）= 未入账，识别特征：无凭证号（VOUCHER_NO）、无入账日期（ACCOUNT_DATE）、FREE_AMT = TOTAL_AMT（全额未分配）。'3'=接收（已生成凭证）、'6'=入账（已记账）
- **正确查法**：须查 **ODS 源表** `BFMSXASA.TASSAA2`（不要查 DWD 加工表——录入状态收条在 DWD 层可能缺失），WHERE `COMPANY_CODE` + `RECEIVE_DATE`（时间范围，必填否则混入历史）+ `RECEIPT_STATUS='0'`

### BR-15 税务规则：应交税费计提/支付/预缴的时间性差异

- **规则描述**：应交税费类负债科目（22 开头）余额变动涉及**计提/支付/预缴三种动作的时间性差异**：计提（SYSTEM_ID=AH）贷记应交税费，支付（SYSTEM_ID=AP）借记应交税费；**支付通常滞后于计提且大部分跨月**（当月支付额可能是上月计提数）。因此贷方发生额≠借方发生额≠余额变动，不能只用"期末=期初+贷-借"公式推导差异
- **正确查法**：差异分析须**逐笔比对凭证明细**（`T_DWD_FACT_CWGL_VOUCHER_DETAIL_INFO`，按 `SYSTEM_ID` 区分计提/支付），结合上下月对比，而非只验证余额公式

### BR-16 收款规则：现金与票据两表并查

- **规则描述**："收款"分两类分布在不同表：现金/直联网银（A13 等）在 `T_DWD_FACT_CWZQ_RECEIPT_DETAIL_INFO`，票据（B71/B72 银票商票）在 `T_DWD_FACT_CWPJ_RAW_PAPER_INFO`。查"某公司收了多少款"**必须两表并查**（沿 linkWith 导航），否则漏掉票据收款。界定"收款时间"用 `RECEIVE_DATE`（收票日期），**不是** `END_DATE`（票据到期日，跨年远期票会混入 2027 年数据）
- **正确查法**：两表分别 WHERE `COMPANY_CODE` + `SETTLE_USER_NAME` + `RECEIVE_DATE`，结果合并统计

### BR-13 应用层口径：标财页面预付款台账金额 = 实时表口径（含待审核）

- **规则描述**：标财应付模块"预付款台账"页面金额是**实时计算口径**：`TAPAPA4` 余额（`ACCT_AMT−CANED_AMT`），**含 LISTING_STATUS=空格的待审核记录**——不等于月末快照表（`T_ZZFX090`）口径。数据库侧不存在任何单一快照表能精确匹配页面金额
- **正确查法**：对账以月末快照（`T_ZZFX090 WHERE YMON=期间 AND BLANCE_AMT<>0`）为基准；解释页面差异用 TAPAPA4 实时口径分解（新增+待审核−已核销−核销进度）。穷尽 ≥3 张表仍无法匹配页面金额时停止搜索，转 EM-004 口径差异识别流程

### BR-17 科目体系规则：账套与科目体系按年度绑定

- **规则描述**：账套↔科目体系是**按年度绑定**的关系（同一账套不同年度可能换体系，但同一年度内一个账套只对应一个体系）。查对应关系表不加 `ACCT_YEAR` 过滤会跨年度混合，产生"跨体系重复"误判。公司代码以 `F100` 结尾的是合并报表用虚拟账套（单体），`ACCOUNT_SYS` 为空或'1'，不参与体系判断
- **正确查法**：`SELECT DISTINCT COMPANY_CODE, COMPANY_CODE_CN, ACCOUNT_SYS FROM BSTAMSCW00.T_DWD_DIM_CWGL_COMPANY_CODE_AND_INNER_CODE_BASE_INFO WHERE ACCT_YEAR='{年度}' AND ACCOUNT_SYS NOT IN (' ','1')`

### BR-18 科目体系规则：同一科目代码跨体系不等于同一科目

- **规则描述**：科目编码和名称可能相同，但**户号/参号类型（ID_CODE_TYPE/REF_CODE_TYPE）不同**（记账辅助核算维度不同），科目的唯一标识 = 科目体系代码 + 科目代码。各体系有"签名维度"：001钢铁→17/14/05/06/19；002贸易→61；106金融→52/64；107宝地→63/70；400工程→62。跨体系按科目代码直接 JOIN/对比会产生语义错误；"匹配率验证体系"是循环论证（已在用的体系匹配率必然最高），有效异常信号是"账套实际科目不在绑定体系内存在"
- **正确查法**：跨体系对比科目 JOIN 条件必须含 `ACCT_SYSTEM_CODE`：`FROM BFMSXAAA.TAAAA02 WHERE ACCT_SYSTEM_CODE='{体系}' AND ACCT_TITLE_CODE='{科目}'`

### BR-19 合并报表规则：合并层用报表项目体系，无科目体系概念

- **规则描述**：会计科目体系用于日常核算（每个账套按年度绑定一个）；**合并报表不用科目体系**，用独立的报表项目体系——各子公司按各自科目体系记账 → 科目到报表项目映射（抵销/调整）→ 汇总到报表项目体系。科目体系不同**不会**给合并报表额外增加问题
- **正确查法**：合并层问题查"合并报表"实体的报表项目类字段（报表项目/报表项目代码1-10/报表项目体系），不要往科目体系上归因

### BR-20 凭证规则：手工/机制凭证的可靠判据（分类描述含"手工"）

- **规则描述**：手工/机制凭证判据 = 凭证分类维度表 `VOUCHER_TYPE_DESC` 含"手工"字样（分类码 AA/EA/EB 等由各账套自定义）。**不可靠判据**：① `PROCED_ID`/`VOUCHER_PROCED_ID` 是否为空（手工凭证也自动生成程式名，实测手工凭证 4092 万条仅 11 条为空）；② 凭证号第 4 位 0/1（手工凭证仅 38% 第 4 位为 0）。凭证号编码结构：1-2 位分类码 + 3 位记账类型 + 第 4 位起序号段 + 流水
- **正确查法**：`SELECT VOUCHER_TYPE, VOUCHER_TYPE_DESC FROM BSTAMSCW00.T_DWD_DIM_CWGL_VOUCHER_TYPE WHERE COMPANY_CODE='{账套}' AND VOUCHER_TYPE_DESC LIKE '%手工%'`

### BR-21 融资规则：借款数据源按账套体系分裂（三套源）

- **规则描述**：借款数据分裂在三套源：**太钢系（24xx 等）→ `V_DWD_FACT_CWZJ_TAFAL91_TG`；宝钢股份系（1xxx）→ 标财 ODS `BFMSXAAL.TAFAL91`；司库/资金系统（如 6701）→ `BSTAMOFM00.T_ODS_V_LOAN_CONTRACT`**。委托贷款类表用 `COMPANY_INNER_CODE`（F 分层编码）关联而非 `COMPANY_CODE`。担保/保函 8 张表仅覆盖 1xxx 账套，查非 1xxx 账套得出"无担保业务"结论须提示用户"可能未采集"，请业务核实
- **正确查法**：查借款先按账套前缀判断体系选源表；查不到时**换源表而不是加宽条件**。借款基本信息↔银行帐户已建 linkWith（`LOAN_BANK_ACCT_CODE = ACCT_CODE`）

### BR-22 应付规则：预付款台账双表口径（快照有效余额 vs 实时含待审核）

- **规则描述**：两套台账口径：① **快照口径** `BFBIFA.T_ZZFX090`（按 YMON 期间分片，有效余额须 `BLANCE_AMT<>0` 过滤——3426 条中仅 314 条有效，对账基准）；② **实时口径** `BFMSXAAP.TAPAPA4`（余额=`ACCT_AMT−CANED_AMT`，含空格=待审核记录，与标财页面一致，见 BR-13）。台账核算科目含 1123 预付账款**和 1221 其他应收款**（非混入）。`TAPAPA5` 是核销记录表（CAV_DATE/CAV_AMT），不是余额表
- **正确查法**：总账查 `T_DWD_FACT_CWGL_GL_TOTAL_AMT_INFO`（END_AMT/LAST_FLAG）；台账快照查 `T_ZZFX090 WHERE YMON='{期间}' AND BLANCE_AMT<>0`；解释页面差异用 TAPAPA4 实时口径

### BR-23 会计规则：宝钢国际账套期末往来科目重分类（正常差异）

- **规则描述**：宝钢国际账套（1029 等）**期末对往来科目红字余额做重分类**（如借 1123900/贷 2202900），**次月初自动红冲**——月末日总账与台账出现阶段性差异属正常，勿判"僵尸余额/异常"。重分类是总账层动作，应付模块台账不体现
- **正确查法**：月末对账差异先排查三因素：① 待审核（BR-22）② 核销进度 ③ 期末重分类（查凭证摘要含"重分类"、科目对 1123900↔2202900）——排除后才考虑异常

### BR-24 凭证规则：红冲凭证金额为负 + 专有标识字段（与 VOUCHER_SORT 无关）

- **规则描述**：**红冲凭证金额一般为负数**；红冲凭证中金额为**正**的 = "红冲了红冲"（二次红冲），通常是误操作信号须逐笔核查。红冲标识字段：`VOUCHER_NO_RED`/`VOUCHER_PERSON_RED` 非空 + 摘要 `VOUCHER_DESC` 含"红冲"（摘要仅凭证基本信息表有，明细表无 VOUCHER_DESC）。`VOUCHER_SORT`（R 收款/P 付款/Z 转账）是记账类型**与红冲无关**。RZ/CZ 前缀中间凭证不在 DWD 表中，多级红冲链须靠摘要文本逐级还原
- **正确查法**：`SELECT VOUCHER_NO, VOUCHER_DESC, VOUCHER_TOT_AMT, VOUCHER_NO_RED FROM BSTAMSCW00.T_DWD_FACT_CWGL_VOUCHER_BASE_INFO WHERE COMPANY_CODE='{账套}' AND ACCT_PERIOD_NO='{期间}' AND VOUCHER_PERSON_RED IS NOT NULL AND VOUCHER_DESC LIKE '%红冲%'`；正数红冲凭证单独列出复核

### BR-25 预算规则：预算实际发生额联动双路径与 FACT_AMT=0 根因

- **规则描述**：预算实际发生额（FACT_AMT）有**两条联动路径**：差旅路径（S/H 类预算科目 ← 公务系统"差旅小秘书"联动）与报支路径（M/Y 类 ← 应付报支系统联动，依赖 `TAPAPM01` 报支对照的 FEE_TYPE_CODE 映射）。注意**空格≠NULL**：FEE_TYPE_CODE 空格=未维护。`V_DWD_FACT_CWZW_COST_BUDGET_CONTROL_TG` 视图仅太钢/宝钢系账套，其他账套查 `T_DWD_FACT_CWZW_COST_BUDGET_CONTROL`

- **正确查法**：`SELECT ... FROM BSTAMSCW00.T_DWD_FACT_CWZW_PAY_BILL_MAIN_INFO WHERE BUSI_TYPE LIKE 'J%'`（费用类）/ `LIKE 'C%'`（采购类）；ODS 源 `BFMSXAAP.TAPAPA1` 同口径

### BR-46 数据覆盖规则：DWD 报支主表选择性覆盖 5.1%——全量统计须直查 ODS

- **规则描述**：`T_DWD_FACT_CWZW_PAY_BILL_MAIN_INFO` 仅同步 **BAO/L20/YAO/WAO/LAO** 5 种单号前缀（88.5 万行），ODS 源 `BFMSXAAP.TAPAPA1` 有 35+ 前缀 1,737 万行，覆盖率 **5.1%**（0821 物理对账实测；同前缀内部另有 ~0.4% 缺失）。BAP/BGW/BFH/BA5/BDP/BO1 等前缀（1,600 万+行）全部不在 DWD——费用类驳回漏 37.2%、采购类漏 84.1%，且查询无任何报错
- **正确查法**：全量统计报支单**直查 ODS TAPAPA1**；DWD 主表仅适合 BAO 等 5 前缀范围内查询；部分缺失前缀有 DWD 分片视图 `V_DWD_FACT_CWZW_TAPAPA1_3K/7Q/CG/E9/KG/O1` 可用（按账套前缀选视图）

### BR-47 收条规则：报账平台发起的转退款无收条号（4X 流水号判据）

- **规则描述**：报账平台发起的转退款**不采集收条信息**——`T_DWD_FACT_CWZQ_RECEIPT_PROCESS.RECEIPT_CODE` 空 ≠ 同步延迟（曾误判），是业务口径。判据：处理流水号以 **4X 开头=报账平台系统别**（⚠️ DWD 层 SYS_ID 字段 68 万行全空未同步，只能从流水号前缀判断）。仅转款类有子收条号（`REFUND_RECEIPT.NEW_SUB_RECEIPT_CODE`）
- **正确查法**：判断转退款发起途径：`SUBSTR(TRANSFER_NO,1,1)='4'` → 报账平台（无收条号）；收条号查 `NEW_SUB_RECEIPT_CODE`（转款类）

### BR-48 资金规则：转退款统计直查处理流水表，TRANSFER_STATUS=7 是常态

- **规则描述**：转退款笔数统计**直接查 `T_DWD_FACT_CWZQ_RECEIPT_PROCESS` 按 TRANSFER_TYPE 分组**（2X=转帐类、4X=退款类、6X=其他）；勿从 `REFUND_RECEIPT`（结果表，同 TRANSFER_NO 一对多且含历史）JOIN 统计（曾 6 条被一对多淹没 67 vs 72）。`TRANSFER_STATUS`：**1=已完成（主力 62 万）、7=报账平台退款常态阶段（18 万，非"未完成"）**、X/0/5/9 待确认——勿据 7 推断"退款未完成"
- **正确查法**：`SELECT TRANSFER_TYPE, COUNT(*) FROM BSTAMSCW00.T_DWD_FACT_CWZQ_RECEIPT_PROCESS WHERE ... GROUP BY TRANSFER_TYPE`；状态分布单独 GROUP BY TRANSFER_STATUS

### BR-49 合并报表规则：抵消分录查法（COMPANY_INNER_CODE 含层级，AO_COMPANY=对方单位）

- **规则描述**：查合并抵消分录（`BFMSR4DC.TR4DCM3` 当前 / `TR4DCM4` 历史）：账套+层级筛选用 **`COMPANY_INNER_CODE`**（如 '6701F200'=账套代码+合并层级后缀，F200/F300/G300 为合并架构层级）；**`AO_COMPANY` 存对方单位代码**（非本账套！曾误用 `AO_COMPANY='6701'` 致漏 36/43 条）。AO_TYPE 抵消类型为 57 种编码（BA 系≈往来类、CA 系≈内部交易类，含义待领域确认）；AO_PERIOD：C=当期、O=期初
- **正确查法**：`SELECT ... FROM BFMSR4DC.TR4DCM3 WHERE COMPANY_INNER_CODE='{账套}{层级}' AND AO_PERIOD='C'`；对方单位分析用 AO_COMPANY

### BR-50 税务规则：涉税"总分"=同税号+不同账套；真税号在 COMPANY_CREDIT_CODE

- **规则描述**：涉税场景"总公司/分公司"判定=**同一税号（统一社会信用代码）+不同账套**。⚠️ `T_DWD_FACT_CWSW_ENTERPRISE_BASE_INFO.COMPANY_TAX_NUM_ADD` **不是税号**（实为 01/02 分类标记，值域实测 空/01/02/NaN）；真实税号=同表 **`COMPANY_CREDIT_CODE`**（18 位统一格式）。总分结转/总分报支场景按此口径识别
- **正确查法**：总分账套识别：`SELECT COMPANY_CODE FROM ...ENTERPRISE_BASE_INFO WHERE COMPANY_CREDIT_CODE='{税号}'`（同税号多账套即总分）；辅 `BFMSXAAA.TAAAAS4` 公司账套对应

### BR-51 报支规则：联络函超时口径（起算=首个分配环节，驳回重录不算）

- **规则描述**：联络函超时计算（`BSTAMOBZPT.T_ODS_TBZPTA1` 头 + `T_ODS_TBZPTA4` 履历，按 BILL_ID 关联）：①**起算点=履历第一个"分配"环节**（REMARK 含"已推送任务中心/任务中心系统自动分配至"，属地审批 OP_TYPE=20 之前），不是 REMARK"推送默认分配人"文本；②**驳回后重新录入的状态不算超时**；③未完结以**当前时间**为截止；④起算人不固定勿假设岗位。OP_TYPE 枚举图库已有（10 提交/20 属地审批通过/21 驳回/30 流转/35 处理成功/80 完结等）
- **正确查法**：履历按 BILL_ID 关联头表，`WHERE REMARK LIKE '%任务中心%'` 定位首个分配环节时间，配合 OP_TYPE 时序推算

### BR-52 票据规则：收条号集团/股份双环境各存一条

- **规则描述**：同一收条号在**集团环境与股份环境各存一条**（用户权威口径）——仅按收条号查询会双环境混合/错账套。环境区分：账套维表 `ACCOUNT_SYS`（用户口径：102/103=集团、001/002/003=股份，待领域确认）或按账套归属判断
- **正确查法**：查收条全生命周期：收条号 + COMPANY_CODE（+必要时 ACCOUNT_SYS 环境区分）；跨表 JOIN 收条号必含账套维度（配合 EM-013）

### BR-53 凭证规则：制单方式源头判据=系统别 AH/AA（维表 T_JXWH03E）

- **规则描述**：手工单据制单 vs 手工凭证制单的**更源头判据=凭证表 `SYSTEM_ID`（系统别）**：**AH=手工单据制单、AA=手工凭证制单**；权威维表 `BFBIFA.T_JXWH03E`（凭证系统别维，已建模）。BR-20 的分类维度 DESC 含"手工"判据仍适用但 SYSTEM_ID 更源头。⚠️ DWS 层 HANDWORK_VOUCHER_TYPE(0/1) 无法区分两种方式；2020 年前未纳入共享中心、制单规范不适用
- **正确查法**：`SELECT ... FROM {凭证表} WHERE SYSTEM_ID='AH'`（手工单据制单）/ `='AA'`（手工凭证制单）；系统别全量枚举查 T_JXWH03E

### BR-54 总账规则：手工单据=功能模块；印花税抛账借 6403105 贷 2221110

- **规则描述**：①"手工单据"是**总账管理下的功能模块名**（含报表导入），非泛指"手工创建的单据"；②手工单据印花税抛账规则=**借 6403105 贷 2221110**；③`BFMSXAAP.TAPAPM3` 是**应付模块**的会计审核抛账规则（其 R09 是代收代付场景，非手工单据规则）；④手工单据抛账真配置在 `BGHDMOBRMN.T_PZ_CONFIG(_DETAIL)`（抛账引擎，页面 GABET00——未建模且无权限）；⑤手工单据画面模版参考 `BSTAMOBCAJ.T_ODS_TAJAH03_JT`
- **正确查法**：手工单据明细查 `T_DWD_FACT_CWGL_MANUAL_BILL_INFO`（44 种 H 开头 BILL_TYPE）；抛账规则区分场景选表（印花税→固定科目；应付审核→TAPAPM3；抛账引擎→PZ_CONFIG）

### BR-55 主数据规则：分中心↔分公司映射权威表 TAUCM29（一码双记录）

- **规则描述**：共享中心分中心代码↔分公司名称的**权威映射藏在权限表**：`BFMSXAAU.TAUCM29`（label"共享部门人员权限"，从"分中心/分公司"语义不可达）的 `SEND_SHARE_CENTER_CODE/SEND_SHARE_CENTER_NAME`——**一码双记录**（"运营共享中心XX分中心"+"宝武共享XX分公司"两行）。⚠️ 勿凭城市/区域名推测归属（C01=上海≠华东分公司）；`COVER_INFO.SHARE_CENTER_BRANCH_CN` 只有城市名（武汉/鄂州）与口语称呼无映射
- **正确查法**：分中心归属查询：`SELECT DISTINCT SEND_SHARE_CENTER_CODE, SEND_SHARE_CENTER_NAME FROM BFMSXAAU.TAUCM29`（两行版本并存按需选择）

### BR-56 报支规则：REJECT_FLAG 是历史标记，驳回后重新提交不清除

- **规则描述**：`PAY_BILL_MAIN_INFO.REJECT_FLAG='Y'` 表示**曾被驳回的历史标记**——重新提交后不清除，最终状态=31（全部付款）时仍为 Y。查"曾被驳回"用 REJECT_FLAG；查"当前被驳回"须结合 `BILL_STATUS=21`。`BACK_TYPE`：1=退回修改、2=退回撤销
- **正确查法**：曾驳回统计：`WHERE REJECT_FLAG='Y'`；当前驳回：`WHERE BILL_STATUS='21'`；两者勿混用

### BR-57 资产规则：末月折旧尾差保残值 + 快照/明细划转差异

- **规则描述**：①**末月折旧额与往期不同=保持账面残值的尾差计提**（正常业务，勿误读为"前几月计提0"）；②快照表（会计期末值）与明细表（处置时点值）对**划转/处置资产**（ASSET_STATUS=59）存在口径差异（划转时点截断，勿判异常）；③DWD 明细表金额存在小数截断（ODS 32.88→DWD 32）；④DWD 数据滞后 ODS 一个月时回退查 ODS（`TAEAEMF/TAEAED1`）
- **正确查法**：折旧尾差核对：明细表逐月折旧额 + 残值 = 原值（逐笔验证）；划转资产（ASSET_STATUS=59）快照/明细差异属正常口径差

### BR-58 收款规则：销货清单→抛账 B1 规则匹配键

- **规则描述**：B1 类抛账规则对销货清单的实际匹配键=**PRODUCT_CODE + AS_BUSI_MAIN_CODE + AS_BUSI_DETL_CODE + COMPANY_CODE**（非 INCOME_TYPE_CODE——该字段在销货清单明细 **91.6% 为空**，不可作主键）；销货清单基本信息表 AS_BUSI_DETL_NAME（如"能介产品"）与明细表对应字段空值不一致属常态
- **正确查法**：抛账规则匹配：`JOIN ON RULE.PRODUCT_CODE=SLIP.PRODUCT_CODE AND RULE.AS_BUSI_MAIN_CODE=SLIP.AS_BUSI_MAIN_CODE AND RULE.AS_BUSI_DETL_CODE=SLIP.AS_BUSI_DETL_CODE AND RULE.COMPANY_CODE=SLIP.COMPANY_CODE`
