# 独立知识跨任务组累计验收

本轮修复知识归属边界：独立知识自身的条件、操作、参数、来源和定义版本决定能否累计与发布；完整任务组只组织案例。范围限于 Memory、其回归与隔离评估脚本，没有修改 Runtime 执行控制或重启宿主，没有写入原账号数据库。

## 已实现的契约

- 每条独立知识有唯一的 user-scoped `experience.independent_knowledge` 账本，候选也保存，默认不参与执行。任务组保存案例快照与版本 binding；这些快照不是验证权威。
- 完整任务组与独立方法分别提名，沿用分窗、预算和模型检查点。独立候选检索使用子方法自身的条件、操作、验证及资源信息，不以领域或完整任务 fingerprint 相同为准入条件。模型可为完整任务选择 new，同时声明对另一组之外的独立知识 support/revise/contradict；程序不按相似度自动归并。
- 支持保留原定义及参数，只加入当前引用且独立的执行。修订保留 knowledgeId、增加定义版本并重新验证，即使文字相同也不继承旧支持。反驳须经显式修订才能重新开放。无关系声明的新命题碰到被占用身份时分配另一 ID，不能覆盖旧版本或隐式增加支持。
- 任务组和账本一次带 CAS 的原子提交。新建断言不存在，任一候选失败回滚全部修订与 epoch。并发纯支持重读最新账本合并；定义变化拒绝陈旧比较，不能复用错误版本。重复 Run、继承结果和已撤回来源不贡献独立支持。
- 执行卡键为 `experience.knowledge:<knowledgeId>`，只指向精确的当前账本 item/revision。召回前后都检查。账本更新后，即使发布中断、旧卡还未挂起，也不能召回旧卡。重试从已提交案例检查点恢复，不重复模型归纳或支持。独立条目不再同时经组 procedure 发布。
- 无关任务组修订不能挂起或恢复独立知识。原始来源撤回、独立修订和反驳仍约束可用性。既有组拥有的旧卡不走兼容读取；历史候选重建需显式隔离评估，不自动把旧组支持导入新账本。

## 程序验证

内存和 SQLite 两种存储验证：不同领域的两个任务仍是两个组，同一子方法经测试模型关系判断只有一个独立账本，累计两个真实执行键并发布一张卡；卡可在新查询中召回。再验证跨组修订暂停、独立再验证、反驳撤回、旧案例不得恢复、继承与重放不累计、并发支持不丢失、陈旧定义拒绝、原始来源撤回、原子回滚、发布中断及恢复。

覆盖文档、代码、外部接口和数据分析的连续回归，保留既有来源、类型、参数、资源隔离和引用归属检查。以上使用确定性测试模型，只证明机制，不证明真实模型识别同一方法的准确率，也不证明线上减少调用或返工。
