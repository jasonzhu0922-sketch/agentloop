# 从当前任务状态出发的行动闭环

日期：2026-11-25。

## 运行契约与首个缺口

目标仍是：用户目标及授权 → 当前有效状态与产物 → 必要历史提示 → 决策和行动 → 提交结果 → 更新下一轮依据。

上次当前精确证据实现解决了“原始结果不能丢、已完成交换不必全部留在原生消息中”，没有稳定解决“本轮行动为何需要、上轮推进了什么”。`1f28c99d` 已能看到首次成功的准备结果，仍四次执行同一准备命令；可选语义更新为零。这是证据到任务进展、任务进展到下一次行动之间的解释和协议缺口，不能用缩短回执解释或修复。

本次把任务进展纳入正常行动契约，继续从正式提交记录派生视图。没有新建状态存储、历史存储或领域流程，也没有赋予模型额外授权。

## 已实现的闭环

每个内核可装饰的普通工具调用，从第一次行动开始，通过现有 `_agentloopContext` 通道携带 `decision`：

- `target`：当前工作对象的稳定标识；是模型使用的主题，不是新 Plan 或授权对象。
- `progress`：现有证据支持的进展及限制。
- `remaining`：仍缺什么、哪些内容未知。
- `purpose`：这次行动如何推进该缺口。
- `evidence`：当前请求能引用的精确证据身份；尚无观察时为空。
- `disposition`：沿用 `retain` / `carry` 内容承接语义。

变化后的循环是：

1. 模型在原本就要发生的决策响应里解释当前进展、选择行动，并提交必要的语义条目变化。
2. 内核冻结本次可见引用和版本，沿用 `assistant.committed` 持久化原始参数及请求依据，然后执行原有授权和工具链。新增字段在宿主工具执行前剥离，Provider 的原始消息与参数保持原样。
3. 正式结果提交后，工作集派生把这份行动前解释与行动的真实结果关联，生成 `currentDecision`。同一批并行动作保留 `parallelDecisions`，不会用最后一个动作覆盖其他动作的目的或结果。
4. 下一轮先看到模型解释、它实际对应的调用、结果身份、调用/操作状态，再根据精确来源更新进展并继续行动。结果缺失或效果未知不会被解释成行动目的已实现。
5. 正常动作所带的 `carry` 使用同一承接集合。当前决策依赖的原文及其行动结果继续保留精确内容；没有当前依赖的已承接细节才可退出常驻输入。持续有效的事实、冲突、未知和承诺继续用既有稳定语义条目表示。

缺失或无效的决策声明产生可见诊断，不改写先前状态，不授权释放来源，也不触发状态维护专用模型调用。宿主同名字段冲突、非对象 schema 保持不透明；不将它们误认成内核声明。

## 权威、版本和恢复边界

`progress`、`remaining`、`purpose` 明确标记 `authority: model`，是当前解释。正式调用结果决定操作事实；CanonicalRunState、用户修订/HIL、产物验证与验收继续决定其原有语义。即使模型写“已经全部完成”，也不能关闭正式 Gap 或提交终态。

内核验证长度、引用、唯一调用身份、Run/Plan/Step 范围、证据必须在本次请求前已提交，以及实际呈现的引用集合。不会引用当前尚未执行的动作作为自身依据。当前依赖加入既有 exact evidence 保护集合，超预算和大窗口继续走原有安全生命周期，不能以不完整引用冒充已读取内容。

承接声明不能证明自然语言解释完整。这一点仍属于模型解释的正确性边界：不能把来源身份合法当作领域结论正确。已有未解决语义条目必须通过显式、带新证据的更新解决；本次行动解释不修改它们。原始正文和事件始终持久化，可以用现有 `read_result` 的 Result、`producer_exchange`、`step_history` 入口恢复细节。

已知成功的同输入、同已观察版本动作现在有精确历史提示 `priorMatchingSuccess`。派生使用按身份、参数及版本计算的散列索引，不向遥测写正文。这个提示只定位先前成功，不证明全部效果相同、不合并写操作，也不阻止合理重复；模型仍需解释重做能带来什么变化。

语义派生与 Provider 编码分离。消息兜底也保留“有行动 checkpoint、无结果”的记录；只有完整、已提交、满足效果与 Provider 条件的原生交换才能释放。reasoning 延续、不完整配对、未知效果和失败写操作继续受保护。重启、取消或 HIL 后能从原事件重建同样的行动解释和未知边界，不重做副作用。

## 各阶段使用同一依据

执行直接消费现有权威视图及新派生的当前行动解释。评估和恢复复用同一工作集派生，并明确区分行动目的与实际结果。

评估取证将当前及并行动作的来源、引用加入既有依赖选择，并保留关联时间线；不因 `carry` 而丢掉仍支持当前解释的来源。已承接且无当前依赖的过程细节可以退出；当前产物、验收缺口、显式必需证据和未知副作用仍受原有规则保护。需要缺失细节时复用已有只读历史查询。

初始规划仍以原始用户要求与现有 canonical 投影为基础；本次没有重新设计 Plan Admission。需要修订计划的恢复阶段使用同一事件和当前工作集，不从模型解释重新生成权威事实。
