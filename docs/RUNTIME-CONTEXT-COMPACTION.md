# Runtime 上下文压缩方法与持久化契约

压缩的目标是让下一次模型调用能够继续正确工作。token 减少是容量条件，不能替代任务、证据和执行连续性。

## 1. 压缩对象与权威边界

Run、Plan、Step、权限、用户决策、原始工具事件、Result、文件版本、验收和 Outcome 继续使用现有 Runtime 权威记录。压缩只改变模型调用的投影，不改写这些记录，不创建另一套业务事实或完成状态。

模型总结只记录进展、依据、未决问题和下一步。它不能批准权限、确认未经核验的事实、替代 Skill 正文、接受交付物或宣布 Run 完成。

## 2. 内容分层决定处理方式

| 内容 | 处理方法 | 保留条件 |
| --- | --- | --- |
| 当前目标、约束、Step 契约、Runtime 指令、用户已确认决策 | 从现有服务端 RuntimeContext 注入，绕过语义总结 | 权威身份和约束不能被摘要覆盖 |
| 工具定义和授权 | 沿用原有授权与暴露机制 | 摘要不能增加或删除权限 |
| 尚未闭合的 ToolCall/ToolResult | 不允许跨越协议边界压缩 | 未闭合协议直接报错 |
| 当前必要的有界读取窗口 | 保留原内容，携带 Result ID、路径、版本、哈希、已读范围和续读位置 | 不能用预览冒充完整读取，不能在下一轮重复取得同一证据 |
| 已提交写入 | 以现有写入回执投影，省略重复写入正文 | 保留文件身份、版本与当前 Run 的提交关系；写入成功不等于验收成功 |
| 已完成查询和历史读取 | 优先使用结构化证据/Result 投影，原始内容继续通过原有身份读取 | 保留来源、覆盖范围、错误、缺口与访问方式 |
| 历史推理、进展、决策依据、未决问题 | 生成有界语义总结 | 区分观测、推断与未验证结论；保留失败和待办 |
| 重复解释、已被替代的草稿、重复大段正文 | 从模型工作集移除，保留持久化原文 | 不能把仍影响当前决策的冲突或约束当作重复内容删除 |
| Skill 正文 | 离开保留窗口后使激活状态过期 | 后续使用必须重新 load_skill，摘要不能代替指令 |

正文不在模型工作集中，不代表数据已删除。需要精确值时读取原有 Result 或文件版本，不依据摘要重造结果。

## 3. 压缩流程

1. **先做确定性投影。** 结构化证据、写入回执和大结果引用先减少重复内容；普通执行和空响应恢复共用此流程。
2. **确定保护区和历史边界。** 只在完整工具交换之间切分，保留当前必要读取窗口，并给摘要留下实际空间。
3. **按调用容量计算预算。** 扣除系统提示、RuntimeContext、工具定义、保留消息、输出预留与安全余量，再计算摘要容量。摘要有期望目标，也有本次调用的可接受上限；二者不能混为一谈。
4. **分块总结历史。** 输入预算同时预留已有摘要和本次输出。超大的已序列化交换按哈希和字符范围连续分片，不能再次截掉尾部回执。每块替换摘要在传入下一块之前先做缩减和预算检查，避免累计摘要撑破下一块请求。
5. **有界缩减，保留较好的候选。** 无效、截断、携带工具调用或更长的缩减结果均不覆盖已有有效摘要。所有调用的用量都计入成本，包括被拒绝的候选。
6. **验收下一次投影。** 摘要必须完整、有规定结构；实际构造的下一次调用投影必须在预算内，且比压缩前更小。目标长度未达到但整体可容纳的有效摘要，可以在已计算的上限内提交。
7. **验收后再提交。** 只有通过后才推进 firstKeptMessageIndex、contextEpoch、摘要与 Skill 过期状态。失败时保留原摘要和历史边界，并记录失败。

连续无效摘要必须显式失败。不能用只保留最近若干 Tool ID 的自动拼接摘要掩盖约束、事实或进度丢失。

结构、哈希、容量和协议检查能确定性验证；语义总结是否完整保留所有业务含义，不能仅凭这些检查证明。因此，影响权限、执行与验收的状态应留在权威层，精确数据应留在可读取的原始证据层，不能只依赖自然语言摘要。

## 4. 每次尝试的持久化

持久化分为 Run 事件和完整诊断正文，使用同一条请求身份关联，不引入业务 Result 身份。

- `context.compaction.started`：源消息边界、源内容哈希、保护区哈希、保留消息哈希、目标与上限。
- `context.compaction.model.requested`：每次生成/缩减调用的身份、阶段、分块和重试序号，以及完整中立 ModelInvocation 的诊断引用。该事件先于模型调用落盘。
- `model.request.started/completed/failed`：模型请求生命周期、耗时、用量、终止原因、已有流回执；Action metadata 携带同一 requestId。
- `context.compaction.model.completed`：完整 ModelResponse 的诊断引用、正文哈希和大小。先保存正文，再执行结构及容量验收；无效和超长返回也保留。
- `context.compaction.summary.rejected`：被拒绝请求身份及原因，例如结构无效、输出截断、缩减未缩短。
- `context.compaction.failed/rejected`：失败详情或整体投影验收失败；不能把有历史可总结但摘要超预算写成“无可压缩历史”。
- `context.compacted`：最终采用的摘要及哈希、前后容量、实际边界、已压缩工具身份、失效 Skill、汇总用量和采用依据。

完整诊断存放在 Runtime 工作区的 `.agentloop/diagnostics/context-compactions/`，目录权限 0700，文件权限 0600，按 SHA-256 寻址，正文写入并刷新后原子重命名，再把引用写入 Run 事件。事件与公开进度只携带诊断引用和统计信息，不内联诊断中的推理正文。

保存的是经过适配器前的中立模型调用和返回，不是带 Authorization 的 HTTP 请求，也不等于原始上游报文；异常 SSE 继续使用已有原始流捕获机制。诊断不自动成为交付物或任务证据。归档时应与引用它的 Run 记录一起保留，不能独立按短期流日志保留策略清理。

## 5. 验证边界

回归覆盖 Result 导航、当前读取窗口、已提交写入关系、Skill 重新加载、无效摘要显式失败、目标与上限分离、只采纳更短的有效缩减、压缩失败保留原状态、整体调用容量验收，以及跨 RunService 实例读取完整诊断引用。

本地测试和构建通过，只能证明源码及持久化契约。上游模型空响应的根因、实际 tokenizer 误差以及新代码在 Local Runtime 的执行效果，仍需独立的上游证据或重启后的真实 Run 验证。
