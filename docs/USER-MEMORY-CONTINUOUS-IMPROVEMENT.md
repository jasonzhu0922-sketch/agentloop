# 记忆准确性、累计与引用的连续实施方案

目标：模型从有界执行证据中归纳可复用知识；每条知识有来源、独立支持和版本，能在后续信息缺口中被引用、验证或修正。范围限于 Memory 及本地证据适配，不改 Runtime 执行控制、业务 Skill、权限或任务完成标准。

## 阶段与顺序

| 阶段 | 实施内容 | 验收契约 | 进度 |
| --- | --- | --- | --- |
| 1. 证据语义 | 区分范围补充与负反馈；保留任务要求、有界交付证据及结果关联，未知关联显式保留 | 补问不撤回支持；补充空检查不冒充最终结果；交付自述不成为来源事实 | 已实现，适配层回归通过 |
| 2. 知识累计 | 模型显式声明对既有知识的支持、修订、反驳；程序绑定稳定身份、版本和当前证据 | 改写可累计；无引用不累计；范围改变不沿用旧验证；重复和继承结果不重复计数 | 组内及跨组独立身份、支持账本与连续机制回归通过；真实模型跨组累计待复验 |
| 3. 独立知识与引用 | 打通独立条目发布和按需召回；保留自身边界、参数、复查及成熟度 | 子方法可独立发布；不依赖整组成熟；资源不符不召回；反驳/撤回立即影响可用性 | 已改为独立账本权威与派生卡，四领域及双存储回归通过；真实产出继续评估 |
| 4. 有界成本 | 按知识类型简化输出；局部错误修正/隔离；沿用分窗与检查点 | 有效独立知识不被无关条目错误拖垮；核心方法和来源边界不被静默修改；重试不重做已通过归纳 | 已实现，真实重放发现的局部引用上下文缺口已修正 |
| 5. 连续验收 | 跨查询、文档、代码、接口的失败契约回归；隔离历史证据重放 | 检查事实保真、知识支持、实际召回与引用、成本；模型质量与程序合同验证分别报告 | 3 个遗留失败样本已在分步重放中完成新增归纳，汇总 9 轮可沉淀；真实独立累计与成熟卡仍未达标 |

## 责任边界

- 模型：尝试/观察/交付的语义解释，知识抽象与适用范围，与旧知识的关系，逐知识支持或反驳判断。
- 程序：中性证据、来源准入、不可变身份和版本、独立执行计数、失效与发布、预算与检查点。不得以错误字符串或领域特例判断原因及通用停止策略。
- 交付内容只作为 Agent 的有界陈述，不能充当工具来源观察或用户认可。缺失目的或关联保持未知。
- 任务组组织案例；知识条目持有自身支持。改写不能丢失证据，扩大前提/范围也不能继承未经覆盖的验证。
- 不把完整对话、工具正文、模型输入输出纳入沉淀；不要求每次执行产生三层知识或必须有新增知识。

## 验收与发布

1. 每阶段先写失败契约回归，再实现，并在本文件记录验证结果。
2. 先验证 Memory 和适配层的聚焦测试，再执行相关全量测试与构建。
3. 历史生产数据库只读；重放写入隔离数据库，不重放实际工具操作，不直接改写在线记忆。
4. 离线模型桩只能证明证据/身份/生命周期；真实模型重放另报准确性、有效支持及成本。真实新任务中的少探索、少返工才是效率证据。
5. 不自动重启其他会话负责的 Runtime，不提交或覆盖无关并行修改。在线应用和历史修复保留为显式运维步骤。

## 实施记录

- 2026-11-19：根据同一对话 9 轮审计建立计划。初始断点：补问被当作纠错；最后补充探查冒充最终结果；知识身份依赖文字内容哈希；部分独立条目错误导致整份归纳重做。现有独立卡、检索、逐知识复核、超量分窗和检查点继续复用。
- 第一阶段：`LocalMemoryFeedback` 与 Reader 共享关系解释。`correct_prior`/disputed 为负反馈；refine/continue 仅保留上下文；未知替代不补造纠错。交付摘录排除表格和代码块、限制到 600 字符，保持模型陈述权威；通过正式 Result 输入图标记来源关系，不猜主结果。
- 第二至三阶段：融合输入提供旧知识 ID 索引；`knowledgeRelations` 声明 support/revise/contradict。支持保留旧命题与边界；修订保留 ID 并清空旧验证支持；反驳停止自动发布。发布和投影使用稳定 ID 与当前内容身份两条关系。四领域连续用例在内存及 SQLite 上验证候选→累计→独立卡→召回→修订暂停→再验证→反驳撤回。
- 第四阶段：局部替换协议只允许已选独立条目或路径评价；附带所属命题、检查标准及限定证据集合。模型可显式撤回独立建议，拒绝项保留审计。未通过修正的可隔离独立条目不进入知识；核心路径、范围、来源身份与隐私仍为硬边界。根对象错误继续整体重生成，已通过检查点继续复用。
- 引用默认由条目持有，逐条评价不再必须重复生成引用；省略评价引用时精确绑定所属条目引用。显式给出越界引用仍拒绝，不自动补成正确。可行动归纳在模型输出契约中明确要求非空执行复盘；缺失复盘是根对象错误，不能靠重写若干评价掩盖。
- 独立条目保留自身参数快照。修订组内其他内容时，未被关系声明替代或反驳的独立条目保留原支持及版本来源，并重新关联本组当前修订发布；不会要求模型每次重写旧条目。未携带独立参数的旧条目遇到参数依赖缺口时不猜测补齐。
- 真实重放发现模型会编造关系目标 ID。融合输出契约现提供已有知识 ID 的精确可选集合，与来源/工具/Skill 引用采用相同处理；跨组归属及来源仍继续硬校验。回归覆盖编造目标不能增加支持、正确目标绑定后仅累计其引用的独立执行，不由程序猜测语义对应关系。
- 关系枚举的局部修正现在保留所属新命题、原合并决定和作用范围。原决定为 reinforce 时，局部修正只能支持或明确撤回关系，不能改成需要全局 refine 的修订/反驳。此修正补齐了生成上下文与可选值；不会自动把非法值映射为 support。
- 本轮验收见 [2026-11-19 评估记录](USER-MEMORY-EVALUATION-2026-11-19.md)。Memory 220 项、本地适配 28 项、多 Runtime 适配 2 项、Desktop 记忆查询/重建 8 项回归通过，Memory 与本地 Runtime 包构建通过。真实模型生成的 22 条知识均为候选，没有独立卡或程序成熟发布，也未形成两个独立执行的有效累计；这部分效果不能用程序回归替代。
- 继续实施关系比较：有历史时保留已接受的独立归纳，模型仅输出组关系、简短理由、逐知识关系与评价；不再重写整份内容。类型、路径评价数量和引用归属进入生成契约。保留原组时的新独立条目仍能留下，并在后续按稳定身份继续累计和发布；支持改写保留原参数定义。最新结果见 [关系比较验收](USER-MEMORY-COMPARISON-EVALUATION-2026-11-19.md)：Memory 230 项及适配/查询/重建 38 项通过，3 个遗留失败样本完成新增归纳；汇总 32 条知识仍全为候选，没有真实的两次独立累计。分步复验结果不能当作单一固定版本的完整纵向通过率。

- 继续实施 C：独立知识拥有 owner scope 内唯一的 `experience.independent_knowledge` 账本，保存自身定义版本、原始执行支持与案例链接；任务组只保存案例快照和 binding。独立候选按子方法自身的条件、操作及资源范围分窗提名，不以完整任务族/领域相同为准入条件；同一次小比较允许新任务组支持旧独立方法。任务组/账本使用一次 CAS 原子提交，纯支持并发可重读账本合并；定义变更拒绝陈旧比较。卡片键只含 knowledgeId，两次召回检查都要求账本当前修订匹配。组内无关修订不再重发或挂起独立卡，独立修订/反驳及来源撤回仍立即影响可用性。Memory 244 项及适配/查询/重建 38 项回归、Memory 与本地 Runtime 构建通过；两轮模型复验初次调用失败，后续再次联网复验均完成归纳；得到 2 条独立候选、各 1 次支持，没有成熟卡或真实跨组累计。详细验收见 [跨组独立知识验收](USER-MEMORY-INDEPENDENT-KNOWLEDGE-EVALUATION-2026-11-19.md)。

## 激活与未完成的效果门槛

- 源码、聚焦回归和构建通过不代表当前长驻进程已加载新版。Memory 使用随宿主进程加载的模块，本轮不重启另一个会话负责的 Runtime。
- 本轮隔离评估不是在线历史修复；旧的错误候选、旧反馈失效标记没有被悄悄重写。若需要恢复被普通补问误撤回的旧支持，应先从原始事件生成目标清单及隔离修订，再按已有 CAS/备份运维流程切换。
- 本轮可确认的是证据、身份、发布和召回的程序契约，以及实际模型重放的样本表现。真实新任务是否减少无效调用、探索和返工，仍需新版进程运行后检验，不能用复核 supported 或离线成功率代替。

## 后续按此顺序推进

| 顺序 | 工作与责任边界 | 通过后再进入下一步的条件 |
| --- | --- | --- |
| A. 固定当前验收基线 | 保存本轮逐 Run 的接受/拒绝、具体错误、知识成熟度及累计成本。保留拒绝结果，不以放宽来源和支持条件提高通过率 | 已区分事实错误、结构错误、关系错误；接受不等于语义完全正确 |
| B. 提高新旧知识关系的稳定性 | 优先处理模型将不同方法/边界误认成 support、引用错配等实测问题；仍由模型归纳语义，程序保留身份和边界。未改变的有效独立条目应持续保留 | 同一方法的独立执行能够真实增加该条支持；普通补问、继承结果和重复重放不能增加；修订必须重新验证 |
| C. 独立知识跨组累计与实际产出（机制已实现，真实产出待验） | 将独立条目的比较与支持累计从任务组合并中分离；任务组只组织案例和完整轨迹。以自身边界检索同一子方法，维护多来源和来源修订约束；再用真实重复子任务检验，不降低成熟门槛凑卡 | 任务整体不同、子方法相同时能保留独立身份和真实支持；至少存在来源可核查、边界完整的成熟独立条目，并能在适用的新任务信息缺口中召回；跨领域实际表现另报 |
| D. 激活并验证应用 | 与负责 Runtime 的会话协调宿主版本；本轮不重启。对新 Run 检查知识 ID/版本、召回投影、后续动作和引用反馈。历史误撤回另走隔离修订/CAS 流程 | 明确证明某条知识在相关动作之前可用且被引用；未命中、命中未用、引用失效分别记录 |
| E. 衡量效率并继续迭代 | 固定版本和样本顺序开展独立评估，按知识条目追踪从沉淀到引用。比较同类任务的信息采集调用、返工及模型用量，连同沉淀成本一起计算 | 已有准确性及引用证据后，才能报告少探索/少返工；没有收益或有误导的知识需由新证据驱动修订或撤回 |

每次迭代先复查上一轮第一个失败的环节；该环节通过后继续推进。确定性测试证明通用机制，真实模型样本证明归纳表现，线上新任务证明应用效果，三者分别记录。调试期间多次修改和恢复失败样本的结果属于问题定位记录，不能充当固定版本、固定顺序的纵向效率评测。

## 隔离评估命令

```bash
node apps/agentloop-desktop/scripts/evaluate-memory-learning.ts \
  --data-dir /absolute/desktop-data --account-id cloud_<账号摘要> \
  --run <Run前缀或完整ID> --run <下一Run> \
  --output /absolute/new-evaluation-directory --with-model
```

不带 `--with-model` 只检查新证据视图，不访问模型。源库始终只读；首次目的目录必须全新且位于账号目录之外。中断后可使用相同参数加 `--resume`，先核对账号、完整有界证据及终态引用，再跳过成功轮次、接续失败或未完成轮次；不会重复生成已接受且输入/提示未变的检查点。报告以临时文件原子替换。

重放按指定顺序从空经验库学习，不导入完整历史库，因此不能将其成本和原来不同批次、历史候选的成本直接当作严格对照。`evidence.json`、`evaluation.db` 和逐轮更新的 `report.json` 分别保留有界证据、隔离知识和调用/拒绝/归纳记录；不重放工具或改在线记忆。成本只累计已返回 usage 的调用，中断或服务未报告的消耗不补造。
