# 计划修订完善与验收

日期：2026-11-17。范围：AgentLoop 共享 Runtime 内核，自动评估恢复与中断恢复；保留 Steer 的用户意图修订语义。

## 核心契约

修订沿用同一用户目标、来源约束、授权边界、Canonical GoalGap 与累计执行修复预算。候选方案被拒是修订诊断，不直接证明目标不可完成。只有通过完整准入和独立评估的方案才能生效；生效的计划、状态、恢复决策必须一致。已完成步骤按引用保留，已有结果按授权绑定消费，未知外部副作用不重放。

## 修订流程

1. 从持久化 Plan、Canonical State、GoalGap、用户决策、当前授权目录和可读 Results 构建修订上下文。
2. 记录候选尝试，生成局部修订；带上之前候选与具体诊断。
3. 依次执行解析、完整准入、持久化定义校验、独立评估。拒绝记录阶段、反馈和证据；在同一候选预算内修正。
4. 以原计划版本、Canonical revision 和 recovery action revision 为前提，原子提交全部生效状态与审计记录。
5. 执行生效的步骤；读取绑定结果，保留已完成步骤；由实际评估关闭 GoalGap。
6. 候选预算耗尽保留具体诊断；缺失用户输入或授权才进入相应等待，不能用确认掩盖证据缺失。执行修复预算不因新步骤或新候选而重置。

## 验收边界

使用隔离数据库和工作区复现；不修改历史 Run，不重放真实外部写入。不自动发布或安装。单元通过、构建通过、真实模型通过、Desktop 重启后通过分别记录，不能互相替代。

## 验收记录

- 实施前：隔离探针确认解析修正可完成，准入/评估拒绝未回送模型，提交中断可造成 Plan v2 + decision rejected；相关现有测试 23/23。

### 完成的实现

- 自动评估恢复与 `advanceRecovery` 共用候选协调流程。每个 Action revision 最多 3 个候选，包含解析失败；预算事件持久化，数据库重开后继续累计。原有每个 Canonical GoalGap 的 2 次执行修复上限保持独立，候选纠错不重置执行预算。
- 拒绝记录保留候选、阶段、错误码、具体反馈及证据引用，提供给下一次规划。计划定义错误使用明确的 `PLAN_NOT_ADMITTED`，评估返回格式错误使用 `ASSESSMENT_ERROR`；数据库和模型服务故障保持原始故障类别。
- 在事务中同时提交 Plan、Canonical State、决策准入、recovery review 完成与生效审计；事务提交后发布计划生效事件。提交前复核 Run 状态、Plan version、Canonical revision 和 Action revision。
- 两种恢复入口使用同一当前授权目录，可重新选择已授权但未绑定到原计划的 Skill。补选仍需完整准入和独立评估；本轮不包含安装新能力或新增外部账户授权。
- 模型可用 `stepReplacements` 明确声明局部替换；Runtime 为受影响且显式保留的未完成依赖步骤创建新身份并改接依赖，保留原始契约、来源和 Result 绑定。未声明时不自动重命名错误定义，已完成步骤继续按持久化引用保留。
- 已提交但未生效的候选在恢复后重新校验，不重新调用模型生成。手动恢复登记执行状态并传递取消信号，拒绝同实例重复推进。
