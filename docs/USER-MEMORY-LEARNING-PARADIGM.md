# AgentLoop 通用记忆沉淀范式

日期：2026-11-17

状态：通用学习契约；第一轮核心实现已落地，具体范围和剩余工作见第 11 节。

本范式规定从一次或多次任务中学习什么、证据能支持什么程度的结论，以及知识如何影响后续任务。适用于编程、研究、写作、数据分析和其他任务；任务中的领域含义由当前 Agent 或 Skill 解释，Memory 负责通用的证据、归纳、适用范围、版本与应用语义。

沿用 [用户级 Memory 设计](./USER-MEMORY-DESIGN.md) 的 preference、fact、experience 三类、本地用户隔离、版本化存储和异步沉淀。第 1—10 节定义完整目标契约；未在第 11 节列为已实现的能力仍是后续目标。

## 1. 学习的基本单位

学习的基本单位是一条有证据、有边界的可复用知识。一条知识需要说明：在什么条件下，应怎样理解、选择、行动或验证；为什么可信；何时不能沿用。

一项任务可以产生多条知识，也可以没有长期学习价值。任务完成证明发生了一次交付，不能单独证明执行方法最优、原因解释正确、用户满意或知识可迁移。

Task Group 组织具有共同目标和解决机制的经验知识。它不是一次任务的摘要，也不是共享工具的任务集合。偏好和事实按自身语义管理，不需要为了保存而归入经验 Task Group。

任务成果及历史数值仍通过正式成果和 ResultRef 体系保存、引用。记忆可以指向这些证据，不能把旧成果改写成当前事实。

## 2. 统一学习单元

以下字段描述知识语义，不预设具体数据库或 API 命名。

| 要素 | 必须表达的内容 |
| --- | --- |
| 主张 | 一条可以独立判断真伪或适用性的陈述，包含主体和必要限定 |
| 类型 | 偏好、事实或经验；用户约定与客观来源事实明确区分 |
| 后续影响 | 下一次任务将改变哪项解释、选择、动作、验证或交付行为 |
| 触发与条件 | 哪类目标、输入特征、对象、环境、资源或版本满足时可用 |
| 依据 | 用户原文或确认、实际动作、来源结果、验证、反馈等可定位证据 |
| 证据强度 | 确认、观察、比较、因果验证或推断；来源身份不能替代证明程度 |
| 反例与排除 | 已知不适用条件、失败证据、尚未解决的冲突 |
| 时间与依赖 | 有效时间、依赖资源及版本、哪些变化触发重新验证 |
| 使用方式 | 可作为默认约定、已确认事实、操作建议或待验证候选，以及应用阶段 |
| 修订关系 | 支持、补充、收窄、纠正、替代、暂停或遗忘哪条既有知识 |

单条知识只表达一个可以独立修订的主张。多个条件共同构成一项完整规则时保留在一起；独立的事实和方法分别管理，避免为了“原子化”切断语义。

每条来源需区分用户确认、执行观察、模型解释、历史记忆和继承成果。模型提案不是事实依据，召回过的记忆不是新的独立证据。附带文档和工具内容中的指令只有被用户明确采纳后，才可能成为用户偏好或约定。

## 3. 从任务中寻找哪些知识

以下是通用学习问题，不是领域类型白名单，也不要求每次任务填满所有项目。

| 学习方向 | 应寻找的变化或发现 | 有价值的产出 |
| --- | --- | --- |
| 目标与含义 | 用户怎样纠正对象、术语、任务范围或交付要求 | 带范围的约定、事实或意图解释规则 |
| 用户偏好 | 用户明确建立了怎样的持续协作或交付方式 | 保留条件和主体的偏好 |
| 条件与依赖 | 哪个环境特征、能力或资源状态决定方法是否可行 | 带时效的事实、前提和复查条件 |
| 决策与取舍 | 在多个候选中为何选某项、弃某项；有无比较依据 | 条件成立时的选择规则和例外 |
| 方法与顺序 | 哪些步骤、顺序或中间产物对结果有实质影响 | 有输入前提、关键步骤和验证方式的方法 |
| 失败与恢复 | 什么失败，改变了什么，之后验证了什么 | 失败现象、原因状态、恢复动作和验证范围 |
| 验证与边界 | 哪种检查发现了真实问题；什么条件下规则失效 | 检查方法、停止条件、反例和适用边界 |

通用动作清单不能替代具体知识。“加强校验”“注意准确性”“充分使用工具”没有说明触发条件和下一步行动，不构成可应用的长期经验。

## 4. 一次任务的提炼步骤

### 4.1 重建实际经历

按持久化证据还原目标、约束、用户决定、实际尝试、结果、验证和反馈。区分计划要做什么与实际做了什么，区分执行成功与交付验证成功。

证据压缩必须保留改变判断的节点：用户纠正、被否定方案、关键失败、恢复后的验证以及未解决缺口。记录压缩覆盖范围和遗漏，不能只保留首尾动作后声称完整。

本地审计证据与沉淀模型输入分别管理。模型接收执行路径、信息采集方式、显式选择与判定依据、验证标准和失败后的调整；模型输入输出、工具返回正文、自由文本结果摘要和完整候选目录不整包进入经验提炼。判定依据来自显式约束、前置事实和检查规则，缺少依据时保留未知，不推测模型内部思考。

同一阶段、同一步骤内等价的成功采集动作合并为方法卡，循环执行保留路径与次数，来源引用仍可定位到每次执行。用户决定、失败转折、方法变化和步骤边界不能被合并消失。同一任务重复调用工具只说明执行次数，不增加独立成功次数。分批和证据窗口处理方法提炼后仍然很大的输入，不能替代这层方法提炼。

### 4.2 找到值得学习的差异

比较初始理解、原计划和最终得到支持的做法，回答：哪里改变了理解或行动，哪项证据促成改变。没有路径调整也可以产生知识，例如首次验证了一个环境前提或一条完整方法。

对每个候选说明“若下次缺少这条知识，具体会多做、漏做或误判什么”。这是评估知识价值的问题，不是已经进行过对照实验的证明。

### 4.3 逐条提出知识主张

从差异和新证据提出独立主张，绑定来源、条件、后续影响、例外及重新验证方式。先表达证据直接支持的最窄结论，再判断是否有依据泛化。

“用户本次选择 A”不能直接改写成“用户以后始终偏好 A”；“执行 A 后成功”不能直接改写成“A 是成功原因”；“查到零条”不能直接改写成“该对象不存在”。

### 4.4 判断成立程度与保存方式

| 单次任务中的依据 | 可以形成的知识 | 不能直接推出 |
| --- | --- | --- |
| 用户明确要求长期保留的偏好或约定 | 按原始条件生效的偏好或事实，成功写入后才确认已记住 | 原文没有授权的更广范围 |
| 用户仅为本次任务选了一个候选 | 可审计的决定；可参与后续归纳的经验候选 | 永久默认值或全局定义 |
| 来源证实环境或资源状态 | 绑定对象、时间、版本的事实 | 环境将一直不变 |
| 一条执行路径完成并通过相关验证 | 限定条件下的一次方法支持证据 | 最优方法或已经成熟的通用 Procedure |
| 有失败、修正、复验的完整链路 | 失败教训和恢复经验候选；因果程度依证据判断 | 同期所有变化都是有效原因 |
| 只有失败现象或一个报错 | 观察、风险提示和待验证假设 | 已确认根因及通用修复规则 |
| 用户纠正前次结论 | 对旧知识的反证或修订依据 | 未被用户说明的新替代事实 |

单次任务足以确认某些事实和用户约定；经验方法进入未来 Planner 的正式 Procedure，仍遵循多次独立验证要求。一次有价值的失败也可以保存教训，不必伪装成成功经验。

### 4.5 允许没有新知识

以下结果均为正常沉淀结果：没有新知识；仅形成候选；补充支持；收窄范围；发现冲突；纠正旧知识。不能为了提高记忆数量，把常识、任务流水或临时输出包装成新经验。

## 5. 多次任务的归纳步骤

### 5.1 先判断能否比较

比较目标、关键约束、输入特征、决策机制、行动路径和验证方式。相同工具、Skill、产物格式或宽泛任务标签只能帮助发现候选，不能证明同一知识可共享。

用户作用域决定哪些证据可以读取，知识适用范围决定哪些证据可以放在一起归纳。一个成本批次可以包含多个目标族，必须分别得出融合结果。

### 5.2 区分重复证据与独立支持

沿成果、结果引用、来源版本和历史记忆使用关系追踪证据依赖。不同 Run 反复复述或读取同一份成果，不能增加独立验证次数。

重复执行可以证明执行稳定性；不同输入可以扩展输入覆盖；不同环境可以扩展环境覆盖；有控制的对比可以增强原因判断。这些支持的结论不同，不合并成一个泛化成功计数。

### 5.3 对每条知识寻找共性与差异

先检验已有主张，再寻找新的抽象：哪些条件始终必要，哪些对象或参数可以替换，哪些差异解释了成功与失败。缺少跨条件证据时保留局部知识，不提前生成跨领域规则。

比较效率、成本和质量时，同时记录任务难度、输入规模、环境及验收标准。不同条件下的一次快慢或成败，不能直接支持“方法 A 优于方法 B”；反复出现的相关性也不能自动升级为因果结论。

一个 Task Group 中的旧知识成熟，不意味着新加入的规则同时成熟。每条规则独立积累支持、反例和验证状态。

### 5.4 输出明确的归纳动作

| 动作 | 含义 |
| --- | --- |
| 新建 | 存在新的、可复用且有证据的知识 |
| 强化 | 主张与范围未变，新增独立支持或可靠性证据 |
| 细化 | 增加条件、参数、步骤或验证方式 |
| 扩展 | 新条件下有独立支持，明确扩展哪些范围 |
| 收窄 | 反例表明原规则过宽，保留仍成立部分 |
| 分离 | 原来混在一起的任务实际依赖不同规则，拆开管理 |
| 纠正或替代 | 新依据推翻旧主张，建立有来源的修订关系 |
| 暂停 | 存在尚未解释的冲突或关键依赖失效 |
| 无新增 | 只有重复证据、无行动价值或证据不足 |

先检查不同范围、不同时间和不同主体能否解释差异；仍然冲突时暂停相关知识的自动应用。不能让“最新一次”无条件覆盖，也不能把一条局部反例扩大成整组知识全部失效。

## 6. 知识晋升的共同条件

候选进入可应用状态，需要同时满足以下要求。模型可以提出判断，来源身份、引用合法性、状态和证据依赖等可确定规则由代码校验；语义判断保留依据和不确定性。

1. **来源真实。** 主张能定位到用户决定、观察或验证，来源引用确实支持所作陈述。
2. **推论适度。** 观察、假设、原因和泛化程度不超过证据强度。
3. **作用明确。** 能说明未来改变的解释、选择、行动、验证或交付行为。
4. **边界完整。** 条件、例外、时间、依赖及复查方式足以决定何时使用。
5. **支持有效。** 经验 Procedure 至少有两次独立的已验证成功支持；次数是必要条件，不替代输入覆盖、方法验证及反例检查。某条失败教训的原因判断还需自身证据。
6. **冲突已处理。** 当前要求与可靠反证不会被旧知识覆盖，未解决冲突不会被当成成熟建议。
7. **应用合规。** 记忆不能新增权限、绕过 Skill 或 Runtime 契约，不能把历史成果当成当前执行证据。

确认过的偏好和事实按各自来源与范围生效，不套用经验 Procedure 的成功次数要求。推断出的长期偏好不能仅凭重复选择静默获得用户确认的权威。

## 7. 跨任务示例

以下仅示范范式，不是现有环境中已验证的事实，也不是业务分支规则。

| 经历 | 适合学习的内容 | 应保留的限制 |
| --- | --- | --- |
| 用户选择本次使用某模板 | 本次选择、候选差异及选择依据 | 没有长期意图时不改成默认模板 |
| 用户要求今后的管理层汇报先给结论 | 条件为管理层汇报的交付偏好 | 不扩大到所有写作任务 |
| 一份文档通过调整表格宽度消除了溢出 | 原页面条件、调整动作及渲染验证 | 未对比时不宣称这是唯一根因或最优排版 |
| 一个软件修复经过隔离变量和回归验证 | 故障条件、确认原因、修复及验证方式 | 绑定相关组件和版本范围 |
| 研究中发现多个网页转载同一原始材料 | 沿来源依赖识别重复证据的方法 | 多个转载不增加独立支持 |
| 用户为某术语确认了真实来源中的对象 | 带来源、上下文和确认依据的映射 | 本次确认与长期约定分别保存 |
| 两次任务出现同样的报错，后来都恢复 | 相同现象及已观察的恢复路径 | 缺少因果验证时不合并成已确认根因 |

## 8. 召回应用后的学习

每次应用分别记录候选召回、范围判断、实际采用、影响位置和结果证据。未采用或需要复核也保留原因。模型声称“使用了记忆”本身不构成采用或有效性的证明。

使用成功只能加强本次证据实际支持的部分。没有相关验证，不能因整个任务完成就强化所有入选记忆；未被采用也不能简单视为知识错误。

用户纠正、资源变化、失败或新反例应触发受影响知识的复评，沿支持关系更新候选、Task Group 和 Procedure。保留历史 Run 的不可变投影；新任务消费新的知识状态。

遗忘既停止未来应用，也阻止同一语义内容从旧经历重新提炼。用户删除一次任务和用户遗忘一条知识具有不同含义，按各自授权处理。

## 9. 实现职责与顺序

| 环节 | 应承担的职责 |
| --- | --- |
| Runtime 证据读取 | 提供实际目标、用户决定、动作、结果、验证、反馈及依赖引用；不编造领域结论 |
| 沉淀模型 | 按本范式寻找学习差异，提出逐条主张和归纳动作，解释范围与证据；允许无学习 |
| Memory 策略和存储 | 校验来源、身份、状态、证据依赖、独立支持、冲突和修订；管理知识生命周期 |
| 召回与投影 | 判断适用范围，保留条件和验证方式，生成有界快照，不丢失主张边界 |
| 当前 Agent 和 Skill | 在当前任务中解释领域含义、核验依赖、决定采用并继续执行正式验证 |

先确定学习单元、证据类型及输出语义，再修改读取器、提炼与融合协议。批处理应支持多个知识组；投影和反馈必须保留单条知识身份，才能把后续反证精确传回。

显式长期要求仍在持久化后及时返回真实回执。隐式经验的提炼和融合仍在本地异步 worker 中执行，不阻塞或改变已经提交的任务 Outcome。

## 10. 验收标准

采用跨写作、编程、研究、数据分析的任务序列验收，避免依赖某个业务名词或特定工具才能通过。

1. 一次任务能同时提出多个独立候选，每条有来源和边界；普通完成任务可以没有新知识。
2. 临时选择不会变成永久偏好；明确长期约定能按其范围保存并在后续适用任务生效。
3. 失败后恢复不能自动证明根因；观察、推断和已证实原因在保存及应用中保持区别。
4. 不同 Run 继承同一成果不会增加独立支持；新增输入或环境验证只扩展相应覆盖。
5. 多目标批次分别归纳；组内旧规则的成熟状态不会自动赋给新规则。
6. 相同工具但不同目标不误合并；不同工具但相同目标和机制可以在证据支持下归纳。
7. 局部反例能够收窄、分离或暂停对应知识；后续纠正能传播到已发布的经验。
8. 召回和投影保留条件、行动与验证；不适用知识不被当作当前约束。
9. 任务完成不自动强化所有召回项；实际采用与结果证据可以追溯到单条知识。
10. 修改与遗忘影响未来应用，历史快照不被覆盖；遗忘的知识不会通过历史重放自动恢复。

验收既看后续行动是否改善，也看是否出现误用、过度泛化、过期事实和错误强化。知识条数、模型调用成功率和 Run 完成数量仅用于运行观测，不能单独代表学习效果。

## 11. 第一轮实现范围（2026-11-17）

### 已实现

1. **统一提炼范式。** 单任务提炼和批量融合共用七个学习方向及证据规则，允许无学习；不把临时选择升级为长期偏好，不把恢复成功当成因果证明。
2. **保留决定与依赖。** 本地读取器从原始 HIL 请求与回答事件保留问题、候选、选中项、identityRefs、计划/步骤引用和确认事件；区分任务意图的模型解释、用户确认和后续纠正。记录正式 prior-result 接续及 Memory 召回引用，保留观测压缩覆盖量。单任务和批处理 Episode 保存脱敏后的证据审计视图。
3. **通用适用范围。** preference、fact、experience 共享一等 applicability；支持文字条件与排除、精确上下文选择器及 validFrom/expiresAt。精确上下文缺失时不召回，范围不同的显式事实或偏好可共存并分别修订。条件在 response、planner、human_loop、execution、artifact 投影中保留。
4. **逐知识验证。** Task Group 中完整经典路径是一项方法，规则和失败教训各自为一项知识，使用内容及范围生成稳定 ID，分别保存来源、支持和 candidate/verified 状态。完整路径的每一步须由同一次执行的证据支持；两次独立支持才发布对应知识。计划、终态和旧组引用本身不增加执行支持；组的累计成功次数不能使新规则直接成熟。
5. **回撤支持。** 已知 prior-result 继承不增加独立执行数；同一 Run 的重放和多个 terminal commit 不重复计数。重新读取后证据变化会撤回旧支持；纠正、争议或验证不成立时，即使模型无新学习或单任务模型暂不可用，也先更新对应知识及 Procedure 的自动召回状态。相同证据重放复用检查点，出版中断可继续。
6. **批处理边界。** 批次按任务指纹与脱敏目标预分组，之后仍由语义模型决定是否与已有 Task Group 融合。经验默认攒批，不足批量的待处理案例达到 5 分钟时可被下一轮 worker 处理；等待本身不消耗尝试次数。计数遵守重试退避和获授权的重放范围。
7. **有界投影与召回证据。** 保留步骤条件、动作、验证、规则和失败细节；预算不足时整项跳过，超大首项不阻塞可容纳的后续项。以目标词项相关性排序，过滤目标完全无词项重合的经验；Runtime 保存 memory.recalled 事件及实际 projection/revision ID。

实现入口：`packages/agentloop-memory/src/{learning-paradigm,knowledge,applicability,semantic-v2,plugin}.ts`，本地证据读取位于 `packages/agentloop-local-runtime/src/memory/local-memory-settlement-reader.ts`，Kernel SPI 及调用位于 `packages/agentloop/src/runtime/{memory-plugin,run-service}.ts`。

### 当前限制与后续工作

- 自然语言条件由当前 Agent/Skill 核验；词项相关性用于建议筛选，不能证明语义适用。Runtime 当前传入任务指纹与目标，其他项目、来源及版本键需要调用方提供，缺失时精确选择器会拒绝匹配。
- 用户本次确认保留为 Episode 证据；隐式学习不自动创建带用户确认权威的长期 preference/fact。长期约定继续通过显式 Memory intake 写入。
- 目前只识别正式 prior-result 接续依赖，尚未覆盖跨 Run 缓存文件、转载来源和多层成果血缘。含 prior-result 的 Run 保守地不增加独立支持，尚不细分其中新增的独立验证。
- 后续反证通过第 15 节的本地反馈调度自动触发重读、回撤和重排；未批量修改真实用户历史库。
- memory.recalled 只证明召回。后续已为新经验投影增加逐知识采用复核（见第 13 节），但它不是因果收益证明，也未接入自动强化。
- 知识身份和支持当前保存在 Task Group revision JSON 中，尚无独立的知识管理 API/UI；旧历史经验的逐知识证据回填、语义遗忘及防止历史再学习的抑制机制仍待实现。
- confirmed 根因要求输入带可引用的因果验证依据；本轮读取器不会根据失败后恢复自动生成此依据。没有该依据时只能保留 inferred/unknown 原因候选。

验证覆盖 Memory 的内存与 SQLite 存储、RunService intake/recall、单任务及批量提炼、真实 Runtime 表结构中的证据读取。验证使用受控模型桩，不代表已发布安装包或真实模型的线上效果验收。

## 12. 参数化经验与历史经验重建（2026-11-18）

沉淀输出在 semanticSettlement/v2 信封内使用 `learningContract=agentloop.reusableLearning/v1`，单任务和融合共用以下结构：

批处理不再把完整目标文本作为知识族的固定分组键。任务类型和领域先限制可比范围；不同目标文本由模型比较实际目标、步骤和观察，按解决机制分组，再用各组的原始执行证据提炼。主体、期间和请求数量变化可以进入同一组；共同工具或宽泛标签不能单独决定归组。分组必须覆盖每个合法案例且恰好一次，遗漏、重复或虚构 ID 会被拒绝。相同目标无需额外分组调用。

- `reuse.parameters` 声明可替换输入，方法中使用 `{{parameter_name}}`，由当前任务或来源绑定。主体、期间、文件、输出要求等不因历史案例固定。
- `classicPath.verification` 表达可重复执行的检查。旧数值、正负号、排名、趋势及缺失观测保留在带上下文和来源的 `caseFacts`，不成为新任务的预期答案。
- `reusableKnowledge.kind=method` 表达方法规则；`scoped_rule` 表达来源限定的知识，例如字段映射。后者必须有 `conditions` 和 `recheckRules`，不会被拼进无条件的规划策略。
- `reuse.verifiedScope` 描述已有执行覆盖；`reuse.unverifiedScope` 明示待验证推广。参数化不证明跨主体、跨时期或跨环境已经成立。

模型负责语义抽象；代码验证结构、参数声明、来源引用、局部知识边界及独立支持。经验相关性仅按结构化方法内容计算，历史答案不参与新任务的方法排序，仍可在审计界面搜索。Planner 投影保留参数和两类范围，不投影 `caseFacts`；规划上下文要求从当前任务绑定参数、复查来源条件。未带新契约的历史经验停止自动召回，仍保留审计。

旧经验通过 Desktop 运维脚本重建，先准备、核对再切换：

```bash
node apps/agentloop-desktop/scripts/rebuild-memory-experiences.ts \
  --data-dir /absolute/desktop-data --account-id cloud_<64位账号摘要>

node apps/agentloop-desktop/scripts/rebuild-memory-experiences.ts \
  --data-dir /absolute/desktop-data --account-id cloud_<64位账号摘要> \
  --apply /absolute/desktop-data/accounts/cloud_<账号>/private/memory-rebuilds/<批次>
```

脚本复用该账号配置的本机沉淀模型。准备阶段从旧经验的原始 Run 引用重新读取执行和验证，在独立数据库中提炼；不把旧摘要改写成新证据。不确定或缺失的来源明确记录。`before.db`、`prepared.db`、`manifest.json` 和 `experiences.md` 用于核对。

应用前复核原始证据、准备文件哈希和已选经验版本；事务中只切换目标账号的经验，新建版本和方法，旧汇总及方法标为 superseded。已选条目的并发修订或删除会拒绝切换，准备期间独立新增的经验会保留。偏好、显式事实、历史投影和原始 Run 保留。`before-apply.db` 与 `applied.json` 保存备份与切换回执。此流程不冒充逐知识采用效果的验收；真实新任务仍须检查召回、实际动作和最终验证。

模型或进程中断后，可用相同账号参数加 `--resume <原重建目录>` 继续。恢复前复核正式经验版本，保留原备份，复用独立副本中已完成的批次检查点；检查点查找不受融合候选数量限制。经校验的语义分组按输入和提示哈希保存，恢复时再次校验完整覆盖，避免重复分组改变已有批次。引用允许每条知识最多 24 个合法来源，以容纳跨案例验证，超限时重新生成而不截掉来源链。

## 13. 逐知识采用复核（2026-11-18，第一阶段）

本阶段借鉴 MemOS 的反馈闭环思路，保留 AgentLoop 的本地存储、revision、来源证据和 Runtime 权限边界，没有引入 MemOS 运行时或数据库。

### 已实现链路

1. **身份贯通。** Planner prior 的 `knowledgeBindings` 保留已验证知识的稳定 ID，指向投影中的完整方法、复用规则或失败教训；候选知识不进入绑定。绑定不重复方法正文，不携带整份支持账本。
2. **不可变快照。** 原召回快照不会因同 ID 重写或进程内引用修改而改变；后续复核读取该 Run 实际保存的快照，不拿当前最新版知识替代历史版本。
3. **异步复核。** 本地 worker 在语义提炼/融合后，调用该设备配置的沉淀模型逐条复核经验应用。每批最多 12 条，不截掉超出首批的知识，不阻塞已提交的 Run Outcome。已有学习检查点与复核检查点分别复用。
4. **引用校验。** 模型只能选择输入中的知识与观测别名；代码要求逐条恰好覆盖并映射回当前 Run 的原始动作、验收引用。采用结论必须有真正执行的动作及步骤；加载 Skill、规划内容或整项任务完成不构成采用证明。执行后失败可以形成采用尝试或反例，未观察到执行的失败不可以。
5. **局部验证。** `supported` / `contradicted` 必须关联同一步骤的相关动作和批准/拒绝验收，且验收必须通过原始 tool call / result 引用确实指向该动作；仅步骤相同不能借用前一次尝试的验收。后续争议或纠正不能被报告为支持。模型仍负责判断证据是否在语义上支持这条知识，结构化引用校验不冒充语义或因果证明。证据不足保留 `unknown` / `unverified`，不能仅凭未找到动作推断未采用。
6. **持久回执。** `local_memory_application_reviews` 保存输入指纹、模型、Run 终态引用、projection/revision/knowledge ID、步骤、依据、结论与错误。输入和来源不变时复用 accepted 检查点；反馈或证据变化生成新快照。无效输出及模型不可用使用原 outbox 的退避与 dead-letter 机制，已经完成的学习不回滚。
7. **查询展示。** Desktop Memory 的 Run 查询页展示逐条采用复核与来源引用。旧数据库缺少该表时仍能只读查询，不会为诊断而迁移数据库；没有记录不等于没有采用。

### 边界与后续阶段

- 当前复核对象为带知识身份的新经验投影。偏好、事实及旧的无身份经验快照不靠猜测补造采用历史；原始 Run 和投影继续保留。
- 复核是有证据引用的模型判断，不能被解释为已经测得成功率、耗时或成本改善。它不增加知识独立支持次数，不授予能力，也不改变任务完成状态。
- 读取器保留的观测仍有脱敏、条数和长度边界。缺失的详细行为或被压缩的证据不会被模型复核补造；可能正常得到无法判断。
- 混合检索和后续反馈调度已在以下阶段补齐；语义遗忘与防止重学仍为后续阶段。真实模型效果需在受控跨任务序列中单独验收；合同测试与浏览器检查不能替代该验收。

## 14. 本地混合检索（2026-11-18）

召回先执行账号、目标、契约版本、激活策略、有效期与精确 applicability 过滤，再对候选融合 BM25 词项、中文字符相似性和任务指纹三路排序，使用 reciprocal rank fusion 保留各路相对顺序。英文常见字母组合不构成方法匹配；空白或无关目标不能只凭相同任务指纹召回经验。偏好、事实的原有优先级及整条方法预算仍保留。

经验文本只取可迁移的方法描述，不把 `caseFacts`、历史答案、审计正文和支持账本作为检索内容。Task Group 搜索复用同一排序器，并保留其任务族过滤。投影 `retrievalReasons` 记录三路信号，便于核查为什么被召回。

该实现完全在本地执行，不依赖新数据库或模型服务；尚不包含神经语义向量索引、同义改写保证或大规模检索性能优化。排序信号不能证明自然语言条件已经满足。

## 15. 后续反馈自动复评与失效隔离（2026-11-18）

本地 Memory 开启后，Runtime 的后台周期先扫描 canonical `conversation.outcome.disputed` / `conversation.outcome.superseded` 事件，再处理结算。每个稳定 Runtime 数据源每轮最多处理 100 个反馈；目标必须属于相同账号和对话，可以位于同一宿主已注册的另一个本地 Runtime 数据库。

反馈先写入 `local_memory_run_invalidations`，隔离使用该 Run 独立支持的旧知识，正在结算的旧作业不能通过后发 publication 恢复召回。无需等待模型即可撤回对应知识支持，并将不足独立支持的方法转为候选或暂停自动召回。随后重排已有历史作业，复用现有提炼/逐条复核检查点、重试和 dead-letter 策略；正在处理的作业完成后再重排。多个 timer 不重入同一 worker。

`local_memory_feedback_cursors` 保存扫描位置及事件身份；重启接续，删除 Run 导致 SQLite 复用 rowid 时会重扫而不跳过新反馈。游标只在回撤及调度成功后推进；遇到处理中的目标保留该事件待重试。未运行的 Runtime 数据库在再次注册后扫描，当前不主动打开所有停用实例。Desktop Run 页面显示反馈失效标记和来源，避免把旧 accepted 复核误解为当前仍可用的支持；旧库诊断仍为只读。

这条链路回撤执行支持，不把用户质疑归因于某条知识，也不删除原始证据、旧 revision 或复核。它尚不是“忘记这一类知识”的语义遗忘：跨改写抑制、禁止重学、显式遗忘入口，以及真实跨场景模型效果评测仍需后续完成。

## 16. 目的、发现与历史融合入口（2026-11-18，第一阶段）

本阶段修复两个信息边界：命令形式相同不代表获取了相同信息；大类兼容不代表历史经验值得融合。

- Runtime 在配置 Memory 插件时提供可选 `record_execution_insight`。Agent 在关键发现、空结果、路径调整或验证后，以简短的目的、发现、信息需求满足状态和下一步引用当前步骤已提交的 Tool Result。Runtime 校验账号、Run、步骤与生产动作，拒绝不存在的引用和引用另一条执行记录形成自证。无需每次工具调用都记录，也不要求每个 Skill 实现独立协议。
- Reader 保留记录与动作的精确关联、执行顺序、脱敏后的发现，以及不含原始值的集合数量和 JSON 选择范围。结构观察受读取边界约束时显式标注不可用或不完整；数量和退出码均不等于信息需求满足。步骤目的通过 `stepOrder` 引用计划，避免逐调用重复传入。
- 方法卡仅合并本地输入和结果身份相同的成功调用。仅有相同命令、参数名称和退出码不能合并；缺失身份保持可区分。原始回执仍保留本地，重复调用不增加独立支持。
- 执行记录属于 `model_interpretation`。记录本身可被引用为解释依据，但不能单独增加方法成功支持、确证原因或替代 Assessment。复用方法仍需真实执行和独立验证。
- 历史融合先以精简的目标、方法、适用边界与检索描述做语义相关性评估，再展开被选中的组和未被组覆盖的提炼 Episode。历史答案、完整来源账本和支持次数不参与初选；词项匹配只影响窗口顺序，不能证明相关，也不能排除跨语言候选。显式任务指纹冲突仍按原边界排除。
- 初选使用同一本地模型，按窗口适配输入预算，保存 `selection` 诊断和绑定当前查询、提示、历史版本的检查点。无效或不可用时走原有重试与失败隔离；不通过忽略历史来掩盖筛选失败。已融合检查点先于筛选查询，保持重放和发布恢复的幂等性。

这一步提供更可靠的学习材料和历史入口。现有历史 Run 没有记录的具体目的与判断原因仍然未知，不从日志补造。独立知识发布与按信息缺口召回的下一阶段见第 17 节；采用后的效果修订仍继续沿用现有契约渐进完善。跨场景合同测试验证编码、文档、调研和数据任务的同一条证据通道；真实模型是否能稳定选择并使用这些知识，仍需新任务验收。

## 17. 执行片段、子任务策略与环境认知（2026-11-19）

三种视角分别回答“实际做了什么”“满足什么条件时怎样行动和验证”“当前资源提供什么能力和含义”。不是逐级晋升流水线，也不要求任务产出全部类型。沿用本地 Run 审计、异步攒批、逐知识支持和 revision，不引入外部记忆运行时。

### 独立知识与成立依据

- L1 继续保存本地审计及有界方法视图。`record_execution_insight` 要求一条发现对应一项有边界的判断；可选 `evidence[{resultId,pointer}]` 从当前步骤已提交 Result 的 JSON 中选择至多 4 个、各不超过 600 字符的精确片段。Runtime 读取原值，Reader 将通过脱敏检查的片段作为独立可引用观察；自由表述仍为模型解释，不获得来源观察权威。
- L2 使用 `reusableKnowledge.kind=method` 表达子任务策略。可选 `operation` 保留已有证据提供的参数化命令、请求、查询或编辑结构，不能猜测接口语法。方法仍需两次独立、已验证成功执行的逐知识支持。
- L3 使用 `kind=scoped_rule` 表达资源/环境认知。声明具体 `resourceContext[{key,value}]`、成立条件及复查规则；只有引用 Runtime 精确选择片段的来源观察，才可按单次来源支持发布。普通执行成功、计划、计数或模型解释不满足该依据。单次观察只支持当前对象和版本下的有界认知，不证明永久有效或普遍规律。
- 只有声明 `standalone=true` 且提供自身完整 `conditions/exclusions` 的知识才单独发布。模型须将必要的父任务条件完整带入；未声明的旧知识继续按原组级边界管理，不自动扩权。独立身份仅依赖自身内容、范围和实际引用参数，父任务增加无关参数不改变身份。
- 单独发布为 `experience.knowledge`，保留知识 ID、版本、逐条证据及来源组引用。方法与认知可在完整路径仍为候选时独立可用。Task Group 负责组织和审计；组级成熟状态不替代单条成熟状态。环境知识不冒充用户确认的 fact 或 preference。

### 执行时按需检索

有 Memory 的 Runtime 提供 `recall_task_knowledge`。Agent 在缺少资源位置、操作方法或验证方式、准备重复探索或遇到意外结果时，使用当前信息缺口查询，传入已识别的资源及版本选择器。无需每次工具调用都检索。

入口只使用 grant 的 Run 身份，并校验访问者；不能指定另一个账号。缺少或不匹配的精确资源选择器直接排除相关知识。每次最多 4 张卡、1600 tokens，预算不足整卡跳过。卡片携带条件、排除项、参数、操作结构和复查规则；不包含原始日志、历史答案、完整来源账本或案例数值。空召回是正常结果，不伪造备用方法。

资源认知在当前资源和版本下重新检查，操作方法从当前任务绑定参数。记忆不能授予工具权限、改变当前步骤目标或替代当前 Skill/Tool 契约与正式验收。独立知识和源组修订不一致、源组删除或冲突、支持被撤回时停止召回；发布中断可通过原融合检查点恢复，不重复调用沉淀模型。

### 采用与验证

检索通过正式 Tool Result 交付，projection 和知识身份持久化。Reader 只把已提交检索结果关联到其后、同一准入步骤实际派发的动作；并发中早于检索提交的动作不能借用知识。检索工具及执行笔记不算方法采用。

异步采用复核同时读取原 Planner 投影和执行知识卡，沿用实际动作及同动作验收的证明要求。复核不增加独立支持，不把总体任务完成、知识可见或模型自述当成效率收益。真实任务的无效调用、探索轮次、返工、耗时及输入规模仍须结合相近条件观察，当前未自动执行奖励强化或生成可执行 Skill。

## 18. 失败任务的候选决策与按需应用（2026-11-19）

任务整体失败，不等于其中没有有用的判断；也不等于失败后的建议已经验证正确。L2 增加 `kind=decision_rule`，表达有条件的停止、重试和换路建议，不把暂时故障包装成永久环境事实或成功方法。

- 每条规则独立声明触发条件、自身前提、排除项、精确资源选择器、复查规则，以及 `decisionPolicy.action/alternatives/resumeWhen`。停止前应检查可改变前置条件的有限动作和已授权替代来源；有效空结果、可修正的请求错误不能直接当作资源不可用。
- 规则须引用当前失败操作及 Runtime 精确选择的有界观察。纯模型解释、旧记忆、任务失败状态、无当前结果的操作都不能提供观察支持。语义是否成立仍须结合证据核验，不用错误字符串决定通用停止策略。
- 有观察支持的规则独立发布为 `experience.knowledge`，卡片标记 `maturity=candidate`、`verificationBasis=execution_observation`、`requiresVerification=true`。允许执行时考虑候选规则，仍需本轮检查前提、排除项、替代路径和恢复条件；不自动进入 Planner 的已验证流程。重复失败或反复召回不能使候选自动成熟；正确性与效率仍需独立的逐判断验证。
- 一般成功方法仍要求两次独立成功执行，来源认知仍要求精确来源观察。各类支持及撤回分别处理；候选规则同样受账号隔离、资源匹配、知识预算、当前源组版本和持久化争议信号约束。既往不可用不证明当前仍不可用。
- Reader 可将 `candidate.repair_stopped` 中要求失败的真实控制事件，关联到同一准入步骤、更早发生且实际执行的失败操作。采用复核可以在“停止前已召回、当前条件成立、控制事件实际发生”的证据下记录采用，即使失败操作早于召回；模型自述停止或只有失败操作不足以证明采用。停止候选循环不等于整个任务终态，不自动形成收益或成功支持。
- 通过校验的融合摘要（包括 `no_learning` 和纠正后的输出）作为有界检查点保存；输入证据、完整提示、模型或准入变化时重新生成。采用评审失败或写组前中断后，复用同一检查点，不再完整调用融合模型。原请求/纠正请求的审计哈希各自保留。每次作业失败另存阶段记录，不再仅依赖会被覆盖的 `last_error`；不保存完整日志、原始模型回复、堆栈或数据库值。

记忆模块提供可复查的建议和采用记录。Runtime 负责失败操作的正式结果保存、评审及终止语义；记忆既不授予权限，也不把阻塞说明当作用户要求的成功结果。

## 19. 模型主导归纳与逐条证据判断（2026-11-19）

总结归纳、方法含义和与旧经验的关系交给大模型；程序负责中性证据、引用准入、支持来源和生命周期，不用业务错误分类规则替代语义判断。

- Reader 的有界方法证据新增 `resultDiagnostics`：只保留声明的状态、结构化错误代码、阶段，以及脱敏后的短诊断消息（最多 240 字符、8 项）。保留 `rowCount/row_count` 等结构计数，缺失不补零。自由文本错误、stderr、工具正文、行值和模型输入输出仍不进入归纳。模型据此区分请求拒绝、成功为空及成功非空，不从 Run 成功反推中间操作成功。
- 有历史候选需要融合的批次/证据窗口，先使用不含旧组内容及其引用的 `extraction` 输入独立归纳，再将 `independentLearning` 交给融合模型比较。没有历史候选时一次归纳即可；不改集批调度，不增加每个 Run 的同步总结。现有精简观察能放入预算时保留供融合核对，超量时使用有界摘要及原引用。两阶段均沿用已有预算、校验、纠正和按输入/模型/提示绑定的检查点，融合失败不会重复生成已接受摘要。独立摘要不足以形成学习时正常结束。
- 模型先输出 `executionReview`，简述尝试、观察、改变和未知，并区分 `observed/inferred/unknown`。随后为路径步骤、方法及失败经验输出 `evidenceAssessment`：支持程度 `supported/tentative/contradicted`、理由、该条引用及局限。该字段不是私有推理过程。程序只检查结构与引用对应关系，不判定业务原因；旧经验不能将新执行改写成另一种机制，Agent 评审不等于用户确认。
- 原有独立成功及精确来源支持条件仍保留，但数量不再充分：新知识还须有模型明确支持的逐条判断。缺少判断、证据不足或被否定的普通方法保持候选；对候选重新计数不能自动成熟。判断变化不改变知识身份，实际前提/范围变化仍产生不同身份。已审证据被撤回或更改后，原判断不能靠补足其他 Run 数量自动续期，须重新归纳；不在此步骤回放或批改历史记忆。
- 被模型否定的决策规则不能作为候选建议召回。可发布知识的局限随 Planner 注意事项或执行知识卡的 `evidenceCaveats` 传递，引用账本仍留在本地审计。停止类失败建议继续保持候选，既不证明总体成功，也不证明节省耗时或调用。

本次边界只覆盖记忆读取、归纳、成熟度及其召回投影；不修改 Runtime 的失败保存、执行控制、Skill 业务逻辑或数据查询系统。离线合同测试证明证据和生命周期契约，真实模型的归纳准确性及效率收益仍需后续新任务验证。
